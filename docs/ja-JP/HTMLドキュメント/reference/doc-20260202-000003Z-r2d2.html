ENUM 再掲要件規約

本書は、HLDocS において

**生成プロンプトを設計・生成する際に、仕様で定義された ENUM 値を再掲すべき条件**を定義する。

本規約は、ENUM 値そのものを定義・列挙・変更するものではない。

また、HLDocS の意味論や document_type 間の関係性を定義するものでもない。

本書の目的は、

生成フェーズにおいて **仕様本文や規約本文が与えられない状況**でも、

LLM が正当な判断を行えるようにするため、

**判断材料として ENUM を再掲すべき条件と制約**を明確にすることにある。

本書は、「HLDocS 前提条件」という仕様が参照可能である場合にのみ適用される。

• 「HLDocS 前提条件」が入力として与えられていない場合、

または当該仕様に基づく適用可否が確定していない場合、

本書に基づく判断・生成・再作成・工程実行を行ってはならない。

• この場合、許可されるのは、

提示された文書の受理および存在確認、

ならびに前提条件が未参照または未確定である旨の通知のみとする。

• 「HLDocS 前提条件」が入力文書一覧に含まれない場合、生成・再作成・成果物提示を一切行ってはならない。

---

1. 生成プロンプトにおける ENUM 再掲要件（MUST）

本章は、生成プロンプト設計において

**仕様で定義された ENUM 値を再掲すべき条件**を定義する。

本章は、ENUM 値の定義・列挙・解釈を行うものではない。

---

2. 再掲の位置づけ

生成プロンプトにおける ENUM の再掲は、

仕様の代替・再定義・要約を目的とするものではない。

ENUM の再掲は、

**LLM が生成フェーズにおいて正当性検証を行うための判断材料を与える行為**

として位置づけられる。

---

3. 再掲が必須となる条件（MUST）

以下のすべてを満たす場合、

生成プロンプトには、該当する ENUM 値を

**逐語かつ不変で再掲しなければならない**。

• 生成対象が、生成プロンプト・テンプレート等の

**HLDocS 構成要素そのもの**である

• 生成フェーズにおいて、仕様本文・規約本文が

**LLM に与えられない**

• ENUM 値が、生成フェーズにおける以下の判断基準として使用される

- 入力検証

- document_type 判定

- Transport Encoding 判定

3.1 Transport Encoding 判定に使用される ENUM（参照先の明示）

本規約における「Transport Encoding 判定に使用される ENUM」は、

Transport Encoding 規約の「transport タグ一覧」に記載された transport 値を指す。

生成プロンプトは、当該 transport 値を判断材料として逐語再掲しなければならない。

---

4. 再掲の方法に関する制約（MUST）

ENUM を再掲する場合、以下をすべて満たさなければならない。

• 再掲内容は **逐語**であること

• 意味変更、要約、補足、省略を行ってはならない

• 再掲された ENUM は **判断材料としてのみ**使用される

• 再掲内容をもって、仕様を上書き・再解釈してはならない

---

5. 再掲が不要なケース

以下の場合に限り、

生成プロンプトに ENUM を再掲する必要はない。

• 当該 ENUM が、生成フェーズにおいて

入力検証・document_type 判定・Transport Encoding 判定の

**いずれの判断にも使用されない**

---

6. 責務の帰属

ENUM 再掲の正当性・完全性・最新性は、

**生成プロンプトを作成・更新する利用者の責務**とする。

仕様が更新された場合における

生成プロンプト側の ENUM 再掲内容の追従は、

自動化を含め、利用者側の運用設計に委ねられる。

LLM は、再掲されていない ENUM を

推測・補完・生成してはならない（MUST NOT）。
