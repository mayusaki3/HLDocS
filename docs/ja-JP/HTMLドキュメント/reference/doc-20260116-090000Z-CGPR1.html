共通ドキュメント生成プロンプト

本プロンプトは、HLDocS において

**すべての document_type に共通して適用される生成・再作成の判断規範**を定義する。

本プロンプトは **prompt（meta）** として成立し、

仕様本文・規約本文が生成フェーズに与えられない状況でも、

LLM が **推測に依存せず機械的に生成処理を実行できること**を目的とする。

本プロンプトは以下を定義する。

• 生成フェーズの内部実行順序（FAIL-FAST 含む）

• 入力検証に必要な判定テーブルおよび ENUM の逐語再掲

• 再作成（recreate / patch）時の不変条件の強制

• document_type = prompt に対する自己参照禁止および new 等価性

• Transport Encoding 適用規則（ui_copy）

---

1. 生成モードおよび操作種別

• mode: `meta`

• operation: `recreate`

本プロンプトは **HLDocS 自身の構成要素（prompt）を生成・再作成するための判断規範**であり、

生成対象は **HLDocS 構成要素そのもの**である。

---

2. 再作成（recreate）における不変条件（MUST）

recreate / patch において、以下は **必ず保持**しなければならない。

• `doc_id`

• `document_type`

• 文書全体の構造順序

• 階層リンク行（先頭および末尾）

以下は禁止する（MUST NOT）。

• 未変更部分の省略

• 「変更なし」「同上」等の参照代替表現

• 推測・補完・再解釈による内容変更

---

3. document_type = prompt に対する特則（MUST）

3.1 自己参照の禁止（MUST NOT）

生成対象となっている **prompt 本文そのもの**を、

以下の目的で判断根拠として使用してはならない。

• 意味解釈

• 制約導出

• 正当性評価

• 差分判断

参照が許可されるのは、以下の **機械的保持に必要な不変項目のみ**である。

• `doc_id`

• `canonical_title`

• `document_type`

• 文書全体の構造順序

• 階層リンク行

3.2 new 等価性（MUST）

同一の仕様・テンプレート・規約が与えられた場合、

document_type = `prompt` における recreate の生成結果は、

**new による生成結果と意味等価**でなければならない。

生成対象 prompt の本文状態（旧版・欠落・乖離）は、

生成結果に一切影響してはならない。

---

4. Phase 0 入力検証用 判定テーブル（逐語再掲）

以下は **Phase 0（入力検証）で使用される判定テーブル**であり、

本プロンプトに **逐語再掲** する。

4.1 document_type 別 supported_modes

• `spec` : `{ meta, apply }`

• `template` : `{ meta, apply }`

• `prompt` : `{ meta, apply }`

• `testspec` : `{ apply }`

• `index` : `{ apply }`

• `note` : `{ apply }`

• `minutes` : `{ apply }`

• `usage` : `{ apply }`

上記に含まれない `(mode, document_type)` の組は **FAIL-FAST** とする。

---

4.2 document_type 別 required inputs（mode 別）

spec

• requires_body_template_by_mode:

- meta: `false`

- apply: `true`

• requires_type_prompt_by_mode:

- meta: `false`

- apply: `true`

template

• requires_body_template_by_mode:

- meta: `false`

- apply: `true`

• requires_type_prompt_by_mode:

- meta: `false`

- apply: `true`

prompt

• requires_body_template_by_mode:

- meta: `false`

- apply: `false`

• requires_type_prompt_by_mode:

- meta: `false`

- apply: `false`

testspec / index / note / minutes / usage

• requires_body_template_by_mode:

- apply: `true`

• requires_type_prompt_by_mode:

- apply: `true`

不足がある場合、生成を開始してはならない（FAIL-FAST）。

---

5. ENUM 再掲（逐語）

5.1 document_type（ENUM）

• `spec`

• `index`

• `template`

• `prompt`

• `testspec`

• `note`

• `minutes`

• `usage`

5.2 Transport Encoding（ENUM）

• `true_out`

• `ui_copy`

---

6. 生成フェーズ内部実行順序（MUST）

LLM は以下の順序を **変更せず** 実行しなければならない。

1. Phase 0: 入力検証（FAIL-FAST）

2. Phase 1: テンプレート抽出

3. Phase 2: テンプレート合成

4. Phase 3: 可変スロット生成および識別子配置

5. Phase 4: 構造トークン実体化

6. Phase 5: Transport Encoding 適用

7. Phase 6: 内部自己検査

8. Phase 7: 最終出力

---

7. Transport Encoding 適用規則（ui_copy）

• 本成果物は `ui_copy` を適用する

• **成果物単位で 1 つのコードブロック**として提示する

• コードブロック外に説明文を出力してはならない

• 外側フェンスは本文中の最大連続バッククォート数 + 1 とする

• 整形は復元可能（roundtrip）でなければならない

---

8. 内部自己検査（非出力・MUST）

以下を必ず検査する。

• 不変項目が保持されていること

• 判定テーブルおよび ENUM が逐語再掲されていること

• 自己参照禁止が守られていること

• 省略・参照代替表現が存在しないこと

• ui_copy 規約に適合していること
