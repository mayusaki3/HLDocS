表示名リンク規約

本書は、HLDocS ドキュメントにおいて、

ドキュメント参照・ファイル参照・パス参照を人間向けに表示する際の

**表示名とリンクの扱い**を定義する。

本書は、物理ファイル名・物理パス・並び順制御用番号を

人間向け表示へ漏出させないことを目的とする。

本書は、「HLDocS 前提条件」という仕様が参照可能である場合にのみ適用される。

• 「HLDocS 前提条件」が入力として与えられていない場合、

または当該仕様に基づく適用可否が確定していない場合、

本書に基づく判断・生成・再作成・工程実行を行ってはならない。

• この場合、許可されるのは、

提示された文書の受理および存在確認、

ならびに前提条件が未参照または未確定である旨の通知のみとする。

• 「HLDocS 前提条件」が入力文書一覧に含まれない場合、生成・再作成・成果物提示を一切行ってはならない。

---

1. 基本方針

HLDocS において、物理ファイル名・物理ディレクトリ名・物理パスは、

ファイル配置およびツール処理のための管理情報である。

これらは人間向け表示名ではない。

したがって、文中で他ドキュメントを参照する場合は、

物理パスまたは番号付きファイル名をそのまま表示してはならない（MUST NOT）。

人間向け表示では、番号なし表示名と Markdown Link を組み合わせて表現しなければならない（MUST）。

---

2. 用語

2.1 物理名

物理名とは、ファイルシステム上のファイル名またはディレクトリ名を指す。

例：

• `01_前提条件.md`

• `00_共通`

• `10_document_type`

---

2.2 物理パス

物理パスとは、リポジトリまたは文書配置上の相対パス・絶対パスを指す。

例：

• `docs/ja-JP/仕様/00_共通/01_前提条件.md`

• `./仕様/00_共通/01_前提条件.md`

---

2.3 並び順制御番号

並び順制御番号とは、ファイル名またはディレクトリ名の先頭に付与される

`NN_` 形式の番号を指す。

例：

• `01_`

• `02_`

• `10_`

並び順制御番号は、共通ドキュメント構造の

「ドキュメント並べ替え番号規定」に従い、意味論を持たない。

---

2.4 表示名

表示名とは、人間向けに表示するドキュメント名・章名・参照名を指す。

表示名には、並び順制御番号を含めてはならない（MUST NOT）。

表示名は、原則として参照先ドキュメントの `canonical_title`、または人間向けに自然な名称を使用する。

---

3. ドキュメント参照の原則

HLDocS ドキュメント内で他ドキュメントを参照する場合、

以下の形式を使用しなければならない（MUST）。

[表示名](相対リンク)

相対リンクには、実際の物理パスを指定してよい。

ただし、リンクテキストには、物理ファイル名・物理パス・並び順制御番号を表示してはならない（MUST NOT）。

---

4. 許可される表記

以下の表記は許可される。

[前提条件](./仕様/00_共通/01_前提条件.md)
[生成プロンプト運用規約](./仕様/00_共通/02_生成プロンプト運用規約.md)
[document_type:spec 仕様](./仕様/10_document_type/spec/01_spec_仕様.md)

理由：

• リンクテキストが番号なし表示名である

• 物理パスは Markdown Link の URL 部分に閉じ込められている

• 人間向け表示に管理用番号が露出しない

---

5. 禁止される表記

以下の表記は禁止する（MUST NOT）。

5.1 番号付きファイル名を表示する表記

[01_前提条件](./仕様/00_共通/01_前提条件.md)
01_前提条件.md を参照する。

---

5.2 物理パスを文中に直書きする表記

docs/ja-JP/仕様/00_共通/01_前提条件.md を参照する。
./仕様/00_共通/01_前提条件.md を確認する。

---

5.3 ディレクトリ番号を表示名として使う表記

00_共通 の仕様を参照する。
10_document_type 配下を確認する。

人間向け本文では、以下のように番号なし表記へ置き換えなければならない（MUST）。

[共通仕様](./仕様/00_共通/01_前提条件.md)

または、文脈に応じて次のように記述する。

共通仕様群を参照する。

---

6. 例外

以下の場合に限り、物理ファイル名・物理パス・番号付き名称を表示してよい。

6.1 コードブロック内

シェルコマンド、設定例、CI 設定、スクリプト、ツール設定など、

物理パスそのものが入力値として必要な場合は、コードブロック内で表示してよい。

例：

cat docs/ja-JP/仕様/00_共通/01_前提条件.md

---

6.2 ツール実装・自動処理仕様

ファイル処理、変換処理、検証処理など、

物理パスそのものを処理対象として定義する必要がある場合は、

物理パスを表示してよい。

ただし、その場合でも、利用者向け説明文では番号なし表示名を併記することが望ましい（SHOULD）。

---

6.3 差分説明・移行説明

ファイル移動、名称変更、リポジトリ構成変更、移行手順など、

物理名そのものを説明する必要がある場合は、物理名を表示してよい。

この場合も、物理名は管理情報として扱い、

ドキュメントの意味論上の名称として扱ってはならない（MUST NOT）。

---

7. 目次・階層リンクでの扱い

目次、階層リンク、関連文書一覧、参照文書一覧では、

番号なし表示名をリンクテキストとして使用しなければならない（MUST）。

許可：

- [前提条件](./仕様/00_共通/01_前提条件.md)

禁止：

- [01_前提条件.md](./仕様/00_共通/01_前提条件.md)

---

8. 生成・再作成時の要件

LLM が HLDocS ドキュメントを生成・再作成・patch する場合、

以下を満たさなければならない（MUST）。

1. 文中に物理パスを直書きしない

2. 文中に番号付きファイル名を直書きしない

3. ドキュメント参照は番号なし表示名＋Markdown Link とする

4. リンクテキストには並び順制御番号を含めない

5. 物理パスを表示する必要がある場合は、例外条件に該当するか確認する

6. 例外条件に該当しない場合は、必ず表示名＋リンクへ変換する

---

9. HTML 可視化との関係

本規約は、Markdown → HTML 可視化における表示名生成の前提規約である。

Markdown 側で物理パスや番号付きファイル名が文中表示されている場合、

HTML 側でも管理情報が利用者向け表示へ漏出する。

そのため、HTML 可視化では、Markdown 上の番号なし表示名を表示テキストとして使用し、

物理パスはリンク先またはメタデータとして扱うことを前提とする。

将来的に HTML に `doc_id` / `sec_id` を埋め込む場合であっても、

表示名は物理名ではなく、canonical_title または番号なし表示名を使用しなければならない（MUST）。
