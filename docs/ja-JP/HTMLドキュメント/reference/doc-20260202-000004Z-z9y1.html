判定テーブル再掲要件規約

本書は、HLDocS において

**生成フェーズ、とくに Phase 0（入力検証）で使用される判定テーブルを、生成プロンプト内に再掲すべき条件と制約**を定義する。

本規約は、判定テーブルの意味論・設計意図・背景を定義するものではない。

また、HLDocS の仕様構造や document_type 間の関係性を規定するものでもない。

本書の目的は、

仕様本文や規約本文が生成フェーズにおいて与えられない状況でも、

LLM が **推測や自然言語解釈に依存せず、機械的に入力検証を行える状態**を保証するために、

判定テーブル再掲の要件を明確化することにある。

本書は、「HLDocS 前提条件」という仕様が参照可能である場合にのみ適用される。

• 「HLDocS 前提条件」が入力として与えられていない場合、

または当該仕様に基づく適用可否が確定していない場合、

本書に基づく判断・生成・再作成・工程実行を行ってはならない。

• この場合、許可されるのは、

提示された文書の受理および存在確認、

ならびに前提条件が未参照または未確定である旨の通知のみとする。

• 「HLDocS 前提条件」が入力文書一覧に含まれない場合、生成・再作成・成果物提示を一切行ってはならない。

---

1. 判定テーブル再掲要件（定義）（MUST）

本章は、生成フェーズ（特に Phase 0: 入力検証）で使用される

判定テーブルの再掲要件を定義する。

1.1 判定テーブルの定義

判定テーブルとは、入力値の組に対して

可否・必須性・分岐結果を **機械的に決定するための値集合**を指す。

1.2 再掲が必須となる条件（MUST）

以下のすべてを満たす場合、

生成プロンプトには当該判定テーブルを再掲しなければならない。

• 判定テーブルが Phase 0（入力検証）またはそれに準ずる工程で使用される

• 当該テーブルを定義する仕様本文・規約本文が、

生成フェーズにおいて LLM に与えられない

• LLM が当該判定を、推測や自然言語解釈を用いずに実行する必要がある

1.3 再掲内容に関する制約（MUST）

• 再掲内容は **値そのもの**、または **機械判定に必要な条件式・真理表のみ**

• 人間向け説明・背景・設計意図を含めてはならない

• 再掲内容の要約・再解釈・補足を行ってはならない

1.4 再掲できない場合の扱い（FAIL-FAST / MUST）

判定テーブルが再掲されていない場合、

LLM は生成を開始してはならない。

---

2. Phase 0 判定用テーブルの再掲義務（運用）（MUST）

本章は、Phase 0（入力検証）で使用される判定テーブルについて、

生成プロンプト側における再掲義務の所在と範囲を明示する。

本章は、判定テーブルの意味・背景・設計意図を定義するものではない。

2.1 対象となる判定テーブル（MUST）

Phase 0（入力検証）で使用される判定テーブルは、以下とする。

• `supported_modes`

• `required inputs`

2.2 再掲内容の範囲（MUST）

再掲される判定テーブルの内容は、以下に限定されなければならない。

• 判定に使用される **値そのもの**

• 判定に使用される **条件式または真理表**

以下を含めてはならない。

• 人間向け説明

• 背景

• 設計意図

• 他仕様への参照注記

2.3 再掲の所在（MUST）

判定テーブルの再掲は、

生成フェーズで参照される **生成プロンプト本文**に行わなければならない。

• 共通生成プロンプトは、document_type 非依存の入力検証に必要な範囲で再掲する

• document_type 別生成プロンプトが Phase 0 判定に関与する場合、

当該プロンプトに再掲する

2.4 再掲できない場合の扱い（FAIL-FAST / MUST）

Phase 0（入力検証）で使用される判定テーブルが再掲されていない場合、

LLM は生成を開始してはならない。

この場合、

不足情報の推測・補完・代替解釈を行ってはならない（MUST NOT）。

2.5 required inputs テーブルへの必須再掲項目（MUST）

`required inputs` テーブルには、

少なくとも以下の行を再掲しなければならない（MUST）。

1. 共通テンプレート new 生成

• mode = meta

• operation = new

• document_type = template

• target = common

• required inputs = 共通仕様を構成する正本仕様群

• prohibited required inputs =

- 既存の共通テンプレート

- 既存の共通生成プロンプト

- document_type 別テンプレート

- document_type 別生成プロンプト

2. 共通プロンプト new 生成

• mode = meta

• operation = new

• document_type = prompt

• target = common

• required inputs =

- 共通仕様を構成する正本仕様群

- 共通ドキュメントテンプレート本文実体

3. 共通テンプレート recreate

• mode = meta

• operation = recreate

• document_type = template

• target = common

• required inputs =

- 共通仕様を構成する正本仕様群

- 修正前正本本文実体

4. 共通プロンプト recreate

• mode = meta

• operation = recreate

• document_type = prompt

• target = common

• required inputs =

- 共通仕様を構成する正本仕様群

- 共通ドキュメントテンプレート本文実体

- 修正前正本本文実体

上記行が再掲されていない場合、

LLM は短い通常運用指示に対する Phase 0 判定を

推測で補ってはならない（MUST NOT）。

この場合は FAIL-FAST とする（MUST）。
