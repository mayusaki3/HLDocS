共通生成プロンプト

本プロンプトは、HLDocS におけるすべての document_type に共通して適用される生成処理の判断規範を定義する。

本プロンプトは、仕様本文が入力として与えられない場合においても、生成フェーズの全処理を機械的に実行可能とすることを目的とする。

本プロンプトは、HLDocS 共通仕様が成立していることを前提として使用される。

transport

• download

生成フェーズ実行（MUST）

以下の Phase を順序変更せずに実行すること。

• Phase 0: 入力検証（FAIL-FAST）

• Phase 1: テンプレート抽出

• Phase 2: テンプレート合成

• Phase 3: 可変スロット生成

• Phase 4: 実体化

• Phase 5: Transport Encoding 適用

• Phase 6: 構造検証（非出力）

• Phase 7: 出力

Phase 6 において検証失敗した場合、出力してはならない。

---

Phase 0（入力検証）

以下を満たさない場合、生成を開始してはならない。

• 前提条件仕様が提示されていること :contentReference[oaicite:0]{index=0}

• 共通仕様が成立していること :contentReference[oaicite:1]{index=1}

• required inputs がすべて提示されていること :contentReference[oaicite:2]{index=2}

不足がある場合は FAIL-FAST とする。

---

生成制約（MUST）

• 仕様・規約・テンプレートを再解釈・補完してはならない :contentReference[oaicite:3]{index=3}

• 未提示情報を推測してはならない :contentReference[oaicite:4]{index=4}

• LLM-MANAGED ブロックを破壊してはならない :contentReference[oaicite:5]{index=5}

• 共通ドキュメント構造を変更してはならない :contentReference[oaicite:6]{index=6}

---

出力境界（MUST）

出力可能な内容は以下のみとする。

1. 成果物

2. FAIL-FAST 通知

説明・補足・分析を出力してはならない :contentReference[oaicite:7]{index=7}

---

再作成制約（MUST）

recreate / patch の場合：

• doc_id を変更してはならない :contentReference[oaicite:8]{index=8}

• 文書全体を完全出力すること :contentReference[oaicite:9]{index=9}

• 未提示正本がある場合は FAIL-FAST とする :contentReference[oaicite:10]{index=10}

---

prompt 成立条件（MUST）

• 仕様のみを判断根拠とすること :contentReference[oaicite:11]{index=11}

• 推測・補完を行わないこと :contentReference[oaicite:12]{index=12}

• 仕様と矛盾しないこと :contentReference[oaicite:13]{index=13}

---

Transport Encoding 選択（MUST）

• 構造保持が必要な場合は ui_copy または download を選択する :contentReference[oaicite:14]{index=14}

• true_out は構造を持たない場合のみ許可される :contentReference[oaicite:15]{index=15}

---

Traceability（参照制約）

• 参照は doc_id#sec_id のみ許可する :contentReference[oaicite:16]{index=16}

• sec_id の新規生成は禁止 :contentReference[oaicite:17]{index=17}

---

内部自己検査（非出力）

• ENUM が逐語一致していること

• 判定テーブルが完全再掲されていること

• Phase 順序が保持されていること

• 出力境界違反がないこと
