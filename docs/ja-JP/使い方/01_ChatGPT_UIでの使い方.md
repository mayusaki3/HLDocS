# ChatGPT UIでの使い方

本書は、HLDocS を **ChatGPT の UI 上で安全に使い始めるための人間向けマニュアル**である。

目的は以下である。

- HLDocS を一度で失敗なく使える状態にする
- UI 特有のコピー・保存時の事故を回避する
- LLM の内部思考を前提としない運用を明確にする

---

## 1. 前提

### 必要なもの

- ChatGPT（Web UI）
- Markdown ファイルを保存できる環境
- テキスト置換ができるエディタ

### HLDocS の基本方針（重要）

- 本書は **人間向け操作手順書**である
- LLM の内部思考（reasoning）は取得・保存しない
- 管理対象は **生成されたドキュメントそのもの**のみとする

---

## 2. HLDocS を使う最小構成

最初に必要なのは、次の 2 ファイルのみである。

1. 共通ドキュメントテンプレート  
2. 共通ドキュメント生成プロンプト  

これらを **そのまま ChatGPT に貼り付けて使用する**。

---

## 3. 基本的な使い方（最初の成功手順）

### Step 1. テンプレートを貼る

ChatGPT の入力欄に、  
「共通ドキュメントテンプレート」の全文を貼り付ける。

---

### Step 2. 生成プロンプトを貼る

続けて、  
「共通ドキュメント生成プロンプト」の全文を貼り付ける。

---

### Step 3. 指示を与える

次のような自然文で指示する。

- このテンプレートを使って  
  docs/ja-JP/使い方/01_ChatGPT_UIでの使い方.md を生成してください
- output_mode は ui-copy でお願いします

※ この段階では、コードブロック記法は使わない。

---

## 4. ui-copy モードでの注意点（非常に重要）

### なぜ ui-copy を使うのか

ChatGPT UI では、次の問題が起きやすい。

- 文中にコードフェンスがあるとコピー時に破損する
- 出力が途中で切れることがある
- ファイルダウンロードはセッション切れで回収失敗することがある

これを避けるため、HLDocS では **ui-copy をデフォルト**とする。

---

### ui-copy の基本ルール

- 出力全体を 1 つのコピー単位として扱う
- 文中に本来コードフェンスが必要な場合は、  
  一時的に `<HL-FENCE>` という文字列に置き換えられて出力される

---

### 保存手順

1. 出力全文をコピーする  
2. 拡張子 .md のファイルとして保存する  
3. エディタで次の置換を **1 回だけ**行う  

   - `<HL-FENCE>` をコードフェンス記号に置換する  

4. 保存する  

これで正規の Markdown になる。

---

## 5. `<HL-FENCE>` を説明する文書について（重要な例外）

`<HL-FENCE>` 自体を説明対象に含む文書では、  
ui-copy を使うと自己言及により構造が破綻する可能性がある。

そのため、そのような文書は次の方法で生成する。

- canonical-md（ファイルダウンロード前提）
- file-only（ui-copy を使用しない）

通常の文書では ui-copy を使用する。

---

## 6. よくある失敗

### 出力が途中で切れる

原因：

- output_mode が指定されていない
- 文書種別に対して不適切な出力モードを使っている

対処：

- output_mode を明示して再生成する

---

### doc_id が変わる

原因：

- 既存ドキュメントを貼らずに再生成した

対処：

- 更新時は **必ず既存ファイル全文を貼ってから指示する**

---

## 7. LLM の思考について（HLDocSの立場）

HLDocS では、次を管理対象としない。

- LLM の内部思考
- 推論過程の逐語説明

正しさは、次によって担保する。

- ドキュメント構造
- doc_id の同一性
- 出力物の整合性
