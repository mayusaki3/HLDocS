# ChatGPT UIでの使い方

本書は、HLDocS を **ChatGPT の UI 上で安全かつ確実に利用するための人間向け手順書**である。

特に以下を目的とする。

- HLDocS を失敗なく利用開始できる状態にする
- UI 特有のコピー不能・構造破壊事故を防止する
- **true_out 相当の出力を明確に禁止**し、再現性を保証する

---

## 1. 前提

### 必要なもの

- ChatGPT（Web UI）
- Markdown ファイルを保存できる環境
- テキスト置換ができるエディタ

### HLDocS の基本方針（重要）

- 本書は **人間向け操作手順書**である
- LLM の内部思考（reasoning）は取得・保存しない
- 管理対象は **生成されたドキュメントそのもの**のみとする

---

## 2. HLDocS を使う最小構成

最初に必要なのは、次の 2 ファイルのみである。

1. 共通ドキュメントテンプレート  
2. 共通ドキュメント生成プロンプト  

これらは **参照データ（添付）として使用**する。

---

## 3. 推奨される使い方（基本手順）

本節の手順は、**最も安定して再現性が高い方法**であり、  
原則としてこの手順を使用する。

### 3.1 基本方針（重要）

- **1 ドキュメント生成 = 1 チャット** を原則とする
- 新規生成時は **必ず新しいチャットを開始**する
- テンプレートおよび生成プロンプトは  
  **本文に貼らず、添付として渡す**

#### 理由

- 過去文脈による誤解釈を防ぐため
- transport 判定（ui_copy / download）を安定させるため
- 説明文・補足文・true_out 相当出力の混入を防ぐため

---

### 3.2 推奨手順（安定運用）

1. 新しいチャットを開始する  
2. 次のファイルを **添付**する  
   - 共通ドキュメントテンプレート  
   - 共通ドキュメント生成プロンプト  
3. 指示文を入力する  

指示文は、冒頭で **添付したテンプレートおよび生成プロンプトに従う**ことを明示する。

#### 指示文の例

（以下は「入力する指示文の内容」を示す例であり、生成対象ではない）

【指示文例：ここから】  
添付したテンプレートおよび生成プロンプトに従い、  
以下の指示を実行すること。

- docs/ja-JP/使い方/01_ChatGPT_UIでの使い方.md を生成する  
- transport は ui_copy を使用する  
【指示文例：ここまで】

#### 注意

- テンプレートやプロンプトを本文に貼らない
- 指示は **簡潔な自然文または箇条書き**で記述する

---

### 3.3 章単位ID（sec_id）を扱う場合の指示

章単位ID（sec_id）は、  
**仕様・テスト仕様・コード間で章単位の紐づけを行う場合にのみ使用する任意機構**である。

常に付与するものではなく、  
**どの章に、何の目的で付与するかをユーザーが明示する必要がある。**

#### 基本方針

- sec_id は **必須ではない**
- **外部から参照される章のみ**を対象とする
- 対象章を明示しない指示は行ってはならない
- 既存の sec_id は **変更させてはならない**

#### 推奨される指示の書き方（例）

【例：sec_id 指示】  
以下の章は、他ドキュメントから参照される前提とする。  
指定した章にのみ sec_id を付与すること。  
既存の sec_id がある場合は変更しないこと。

対象章：
- 3. 認証トークンの失効  
- 5. セッション無効化条件  
【例：ここまで】

#### やってはいけない指示（NG）

すべての章に sec_id を付けてください

このような指示を与えると、  
LLM が判断を行い sec_id を乱発・誤生成する原因となる。

---

## 4. 添付が使えない場合の代替手順（例外）

本節の手順は、**推奨手順が成立しない場合のみ使用を許容**する。

### 4.1 この手順を使用してよい条件

- 添付が途中で切れる
- UI が添付を受け付けない
- セッション切れが頻発する
- 一時的な検証・デバッグ目的

---

### 4.2 代替手順（フォールバック）

1. 新しいチャットを開始する  
2. 共通ドキュメントテンプレート全文を貼る  
3. 共通ドキュメント生成プロンプト全文を貼る  
4. 指示文を入力する  

#### 位置付け（重要）

- この方法は **常用しない**
- 成功しても、**安定運用ではない**

---

## 5. 出力・transport に関する厳格ルール（最重要）

本章は、**true_out 相当出力による失敗を防止するための絶対規約**である。

### 5.1 MUST（必須）

以下は **必ず守らなければならない**。

- 出力は **1 つのコードフェンスのみ**で構成されること
- 出力内容は **Markdown 全文**であること
- transport は **ui_copy または download のみ**を使用すること
- **コードフェンス外に文字列を一切出力しない**こと
- ui_copy の場合、内容は **roundtrip 可能**であること

### 5.2 MUST NOT（禁止）

以下に該当する出力は **すべて失敗扱い**とする。

- true_out を使用する、またはそれに相当する出力
- コードフェンス外に説明文・補足文・空行・記号が存在する
- 複数のコードフェンスが存在する
- コードフェンス内にコードフェンス記号が含まれる
- Markdown をコピーできない UI 出力

### 5.3 失敗時の扱い

- 上記 MUST / MUST NOT に **1 つでも違反した場合**  
  → **成果物として採用してはならない**
- 必ず **条件を明示した上で再生成**すること

---

## 6. ui_copy モードでの保存手順

1. 出力全文（コードフェンス内）をコピーする  
2. 拡張子 `.md` のファイルとして保存する  
3. 必要に応じて置換・検証を行う  
4. 正規成果物として管理する  

---

## 7. 引継ぎ情報を用いて新しいチャットに移行する場合の手順

HLDocS の検討・設計・デバッグ作業を **新しいチャットに引き継ぐ場合**は、  
以下の手順を推奨する。

### 7.1 基本方針

- 引継ぎ情報は **前提条件の共有**であり、命令ではない
- 引継ぎ情報を貼っただけでは、LLM は生成を開始しない
- 必ず **引継ぎ後の作業指示**を明示する

### 7.2 推奨手順

1. 新しいチャットを開始する
2. 引継ぎ情報（整理済みテキスト）を貼り付ける
3. 続けて、**引継ぎ後の作業指示**を貼る
4. 必要なテンプレート／プロンプトを添付する
5. 生成を開始させる

### 7.3 引継ぎ後の作業指示の例

以下は、引継ぎ情報の直後に貼る **最小指示例**である。

【指示例：ここから】  
上記引継ぎ情報を前提として、  
共通ドキュメント生成プロンプトの差し替え版（全文）を作成する。

- 差し替えとは全文置換を意味する  
- 変更履歴・改訂注記は一切含めない  
- ui_copy 指定時に、本文中の ``` を削除せず、必ず変換保持することを強制する  
【指示例：ここまで】

この形式により、

- 「整理の再掲」
- 「引継ぎ内容の評価」
- 「メタ説明のみの応答」

に逸脱することを防げる。

---

## 8. LLM の思考について（HLDocS の立場）

HLDocS では、次を管理対象としない。

- LLM の内部思考
- 推論過程の逐語説明

正しさは、次によって担保する。

- ドキュメント構造
- doc_id の同一性
- 出力物の完全性（コピー可能であること）
