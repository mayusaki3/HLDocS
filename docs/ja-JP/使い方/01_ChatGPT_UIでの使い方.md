# ChatGPT UIでの使い方

本書は、HLDocS を **ChatGPT の UI 上で安全に利用するための人間向け手順書**である。

目的は以下である。

- HLDocS を失敗なく利用開始できる状態にする
- UI 特有のコピー・保存時の事故を回避する
- LLM の内部思考を前提としない運用を明確にする

---

## 1. 前提

### 必要なもの

- ChatGPT（Web UI）
- Markdown ファイルを保存できる環境
- テキスト置換ができるエディタ

### HLDocS の基本方針（重要）

- 本書は **人間向け操作手順書**である
- LLM の内部思考（reasoning）は取得・保存しない
- 管理対象は **生成されたドキュメントそのもの**のみとする

---

## 2. HLDocS を使う最小構成

最初に必要なのは、次の 2 ファイルのみである。

1. 共通ドキュメントテンプレート  
2. 共通ドキュメント生成プロンプト  

これらは **参照データ（添付）として使用**する。

---

## 3. 推奨される使い方（基本手順）

本節の手順は、**最も安定して再現性が高い方法**であり、  
原則としてこの手順を使用する。

### 3.1 基本方針（重要）

- **1 ドキュメント生成 = 1 チャット** を原則とする
- 新規生成時は **必ず新しいチャットを開始**する
- テンプレートおよび生成プロンプトは  
  **本文に貼らず、添付として渡す**

#### 理由

- 過去文脈による誤解釈を防ぐため
- ui_copy / transport 判定を安定させるため
- 説明文・補足文の混入を防ぐため

---

### 3.2 推奨手順（安定運用）

1. 新しいチャットを開始する
2. 次のファイルを **添付**する  
   - 共通ドキュメントテンプレート  
   - 共通ドキュメント生成プロンプト
3. 指示文を入力する

指示文は、冒頭で **添付したテンプレートおよび生成プロンプトに従う**ことを明示する。

#### 指示文の例

（以下は指示文そのものを示す例であり、生成対象ではない）

```markdown
添付したテンプレートおよび生成プロンプトに従い、  
以下の指示を実行すること。

- docs/ja-JP/使い方/01_ChatGPT_UIでの使い方.md を生成する  
- transport は ui_copy を使用する  
```

#### 注意

- テンプレートやプロンプトを本文に貼らない
- 指示は **簡潔な自然文または箇条書き**で記述する

---

### 3.3 章単位ID（sec_id）を扱う場合の指示

章単位ID（sec_id）は、  
**仕様・テスト仕様・コード間で章単位の紐づけを行う場合にのみ使用する任意機構**である。

常に付与するものではなく、  
**どの章に、何の目的で付与するかをユーザーが明示する必要がある。**

#### 基本方針

- sec_id は **必須ではない**
- **外部から参照される章のみ**を対象とする
- 対象章を明示しない指示は行ってはならない
- 既存の sec_id は **変更させてはならない**

#### 推奨される指示の書き方（例）

```markdown
以下の章は、他ドキュメントから参照される前提とする。  
指定した章にのみ sec_id を付与すること。  
既存の sec_id がある場合は変更しないこと。

対象章：

- 3. 認証トークンの失効
- 5. セッション無効化条件
```

#### ref と併用する場合の指示例

以下の章は testspec から参照される。  
そのため sec_id を付与し、ref で参照可能な形式にせよ。  
sec_id の形式は hldocs 規約に従うこと。

#### やってはいけない指示（NG）

すべての章に sec_id を付けてください

このような指示を与えると、  
LLM が判断を行い sec_id を乱発・誤生成する原因となる。

---

## 4. 添付が使えない場合の代替手順（例外）

本節の手順は、**推奨手順が成立しない場合のみ使用を許容**する。

### 4.1 この手順を使用してよい条件

- 添付が途中で切れる
- UI が添付を受け付けない
- セッション切れが頻発する
- 一時的な検証・デバッグ目的

---

### 4.2 代替手順（フォールバック）

1. 新しいチャットを開始する
2. 共通ドキュメントテンプレート全文を貼る
3. 共通ドキュメント生成プロンプト全文を貼る
4. 指示文を入力する

#### 位置付け（重要）

- この方法は **常用しない**
- 成功しても、**安定運用ではない**

---

## 5. ui_copy モードでの注意点

### 5.1 ui_copy の目的

- ChatGPT UI 上で **安全にコピー・保存**するため
- 正規内容（canonical）を壊さず回収するため

---

### 5.2 ui_copy の前提（重要）

- 出力は **単一のコードブロック**
- コードブロック外に文字列は出力されない
- 内容は **復元可能（roundtrip）な Markdown 全文**

※ これは `05_Transport_Encoding規約.md` に準拠する。

---

### 5.3 保存手順

1. 出力全文をコピーする  
2. 拡張子 `.md` のファイルとして保存する  
3. 必要に応じて置換を行う  
4. 保存する  

---

## 6. `<HL-FENCE>` に関する補足

- `<HL-FENCE>` は **過去の ui_copy 実装との互換説明**
- 現在の標準 ui_copy では **通常使用しない**
- `<HL-FENCE>` 自体を説明対象に含む文書のみ例外とする

---

## 7. よくある失敗

### 出力が途中で切れる

原因：

- transport が指定されていない
- 添付方式を使わず、貼る方式を使用している

対処：

- transport を明示する
- 推奨手順（添付方式）で再生成する

---

### doc_id が変わる

原因：

- 既存ドキュメントを貼らずに再生成した

対処：

- 更新時は **必ず既存ファイル全文を貼ってから指示する**

---

## 8. LLM の思考について（HLDocS の立場）

HLDocS では、次を管理対象としない。

- LLM の内部思考
- 推論過程の逐語説明

正しさは、次によって担保する。

- ドキュメント構造
- doc_id の同一性
- 出力物の整合性
