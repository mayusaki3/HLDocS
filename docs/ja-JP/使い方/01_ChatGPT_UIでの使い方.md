# ChatGPT UIでの使い方

本書は、HLDocS を **ChatGPT の UI 上で実際に使い始めるための人間向けマニュアル**である。

本書の目的は以下である。

- HLDocS を「一度、失敗なく使える」状態にする
- UI 特有の制約（コピー・保存時の事故）を回避する
- LLM の内部思考を前提としない運用方針を明確にする

---

## 1. 前提

### 必要なもの

- ChatGPT（Web UI）
- Markdown ファイルを保存できる環境
- テキスト置換ができるエディタ

### 本書の前提方針（重要）

- 本書は **人間向けの操作手順書**である
- LLM の内部思考（reasoning）は表示・取得・保存しない
- LLM は **生成結果（ドキュメント）のみを管理対象**とする

---

## 2. HLDocS を使う最小構成

最初に必要なのは、以下の 2 ファイルのみである。

1. 共通ドキュメントテンプレート.md  
2. 共通ドキュメント生成プロンプト.md  

これらを **そのまま ChatGPT に貼り付けて使用する**。

---

## 3. 基本的な使い方（最初の成功手順）

### Step 1. テンプレートを貼る

ChatGPT の入力欄に、  
「共通ドキュメントテンプレート.md の全文」を貼り付ける。

---

### Step 2. 生成プロンプトを貼る

続けて、  
「共通ドキュメント生成プロンプト.md の全文」を貼り付ける。

---

### Step 3. 指示を与える（例）

次のような **自然文の指示**を入力する。

- このテンプレートを使って  
  docs/ja-JP/使い方/01_ChatGPT_UIでの使い方.md を生成してください  
- output_mode は ui-copy でお願いします

※ この時点ではコードブロックを使わない。

---

## 4. ui-copy モードでの注意点（非常に重要）

### なぜ ui-copy が必要か

ChatGPT UI では：

- コードフェンスが含まれるとコピー時に破損しやすい
- 出力が途中で切れることがある

そのため ui-copy モードでは：

- 文中のコードフェンス記号を ^^^ に退避する
- 出力全体を 1 つのコードフェンスで囲む

---

### 保存手順

1. 出力全文をコピーする  
2. 拡張子 .md のファイルとして保存する  
3. エディタで次の置換を **1 回だけ**実行する  

   - ^^^ を ``` に置換する  

4. 保存する  

これで **正規 Markdown（canonical-md）になる**。

---

## 5. よくある失敗

### 出力が途中で切れる

原因：

- ui-copy が指定されていない
- コードフェンスが本文中に含まれている

対処：

- output_mode を明示して再生成する

---

### doc_id が変わる

原因：

- 既存ドキュメントを貼らずに再生成を依頼した

対処：

- 更新時は **必ず既存ファイル全文を貼ってから指示する**

---

## 6. LLM の思考について（HLDocSとしての立場）

HLDocS では：

- LLM の内部思考は **管理・保存対象外**
- 人間が読む・検証する必要はない
- 正しさは **構造・ID・出力物**によって担保する

そのため本書および HLDocS 準拠文書では：

- 思考過程の開示
- 推論の逐語説明

を要求しない。

---

- 翻訳ドキュメントを生成する
- 複数ファイルを同時に管理する
- API 利用・自動検証（将来）
