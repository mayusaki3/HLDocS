# ChatGPT_UIでの共通仕様生成・検証手順

## 位置づけ（IMPORTANT）
- 本書は **仕様（spec）ではない**。
- 本書は **人間向けの運用手順（note）**である。
- HLDocS 共通仕様そのものを定義・変更・補完しない。
- 目的は、**検証対象の混線・暗黙工程・前提のすり替わり**を防ぎ、  
  **LLM 主導で検証が回る状態を安定再現**することである。

---

## 何を解決するための資料か
- 検証が進むにつれ、  
  - どの文書が検証対象か  
  - どの判断が仕様準拠か  
  が曖昧になる問題を防ぐ。
- **作業指示（統括）**と**検証実行**を分離し、  
  人間は「貼る・回収する・判断する」だけに集中できるようにする。

---

## 想定する使い方（要約）
- 人間は **作業指示チャット**を起点に、検証の枠組みだけを整える。
- 検証の具体手順・質問・次アクションは **LLM が提示**する。
- 人間は **検証チャット**で LLM の指示どおり実行し、結果を回収する。
- 問題があれば、LLM が **質問作成 → 原因特定 → 修正指示**を主導する。

---

## 役割分担（重要）

### 作業指示チャット（統括）
**人間が行うこと**
- 検証の目的を簡潔に示す（例：成立判定のみ／生成可否の確認 等）
- **共通仕様一式（01〜11）と必要なテンプレート**を提示する  
  - 添付数制限がある場合は、**分割して提示してよい**（分割した旨を明示）
- 検証チャットから回収した結果を評価し、  
  合否・是正要否を判断する

**このチャットで行わないこと**
- 検証ロジックの記述
- 仕様解釈の即断
- 実行（生成・再作成・工程実行）

### 検証チャット（実行）
**人間が行うこと**
- 作業指示チャットで **LLM が作成した指示文**と  
  **指定された添付文書**をそのまま貼る
- 応答結果を **作業指示チャットに回収**する

**検証チャット側の期待挙動**
- 判断根拠は **添付文書本文のみ**
- 前提未成立時は **生成せず拒否**が正解
- 次工程・質問・是正案は **LLM が提示**

---

## どう始めるか（最小手順）
1. **新しい作業指示チャット**を開始する。
2. **共通仕様一式（01〜11）**と、検証に必要なテンプレートを提示する  
   - 分割提示可（分割時は明示）
3. 検証の目的を **一文で**示す（例：「成立判定のみを実施」）。
4. 以降は、作業指示チャットで **LLM が提示する指示**に従う。

※ 検証チャットに貼る具体文言は **検証内容に応じて LLM が作成**する。  
※ 本書に **固定の指示文は存在しない**。

---

## 添付文書の考え方（人間向け）
- 検証対象は **常に HLDocS 仕様**のみ。
- 「参照」「前回の続き」「暗黙前提」は不可。
- **HLDocS 前提条件（spec）**は必須。
- **ENUM 再掲要件規約（10）／判定テーブル再掲要件規約（11）**は  
  共通仕様一式に含まれる前提として提示する。

---

## 検証後の進め方（概要）
- 問題あり：  
  LLM が **質問作成 → 人間が検証チャットで実行 → 結果回収 → 原因特定 → 修正指示**  
  → **最初から再検証**
- 問題なし：  
  次の検証ステップへ

---

## まとめ
- 本書は **人間向けの開始ガイド**であり、逐次操作マニュアルではない。
- **何を貼れば始められるか**だけを明確にする。
- 検証の中身は **LLM 主導**で回す。
