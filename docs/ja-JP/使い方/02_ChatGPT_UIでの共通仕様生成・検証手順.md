# ChatGPT_UIでの共通仕様生成・検証手順

## 1. 目的と位置づけ

本書は、**HLDocS 共通仕様に基づく生成・検証作業を「開始できる状態」にするための手順書**である。  
逐次操作マニュアルではなく、  
**「どうすれば始められるか」**を定義することのみを目的とする。

本書が対象とする課題は以下である。

- 検証統括と検証実行が同一チャットに混在する
- 共通仕様が未成立のまま生成・評価が進行する
- 検証が人間主導となり、LLM 主導ループが成立しない

本書はこれらを防ぎ、  
**LLM 主導で共通仕様生成・検証が回り始める初期状態**を作るための資料である。

---

## 2. 想定する運用環境

本手順は、ChatGPT のチャット画面を 2 つ使用する運用を前提とする。  
いずれも 新しいチャットとして開始する。  
この 2 つのチャットは、役割が明確に分離されており、混在させてはならない。

---

### 作業指示チャット

作業指示チャットは、検証全体を統括するためのチャットである。
ここで行われるのは、以下に限定される。

- 共通仕様の成立可否判定
- 実施すべき検証内容の整理（検証ロードマップの提示）
- 検証チャットで実行すべき指示文の生成
- 検証結果の評価
- 想定外の結果が出た場合の調査指示
- 仕様に問題があると判断した場合の修正指示

検証作業そのもの（生成・判定・拒否など）は、**このチャットでは実行しない。**  
検証の過程で問題が発生した場合、作業指示チャットは、

- 調査のための指示を生成する
- 調査結果を踏まえて、必要に応じて仕様修正を指示する
- 修正後は、検証を最初からやり直す

という役割を担う。

---

### 検証チャット

検証チャットは、作業指示チャットから与えられた指示を実行するためのチャットである。  
人間は、作業指示チャットの指示に従って、

- 指示文を貼り付ける
- 必要な文書を添付する
- その結果を回収する

という操作のみを行う。  
検証チャットで得られた結果は、そのまま作業指示チャットに戻され、評価に用いられる。

---

この 2 つのチャットの分離は、単なる運用ルールではなく、
**本手順が成立するための前提条件**である。  
この前提が守られない場合、以降の検証は正しく機能しない。

---

## 3. どう始めるか（標準手順）

以下を行えば、検証を開始できる。

### 手順

1. **新しい作業指示チャットを開始**
2. **共通仕様一式**と必要なテンプレートを添付  
   - 分割添付可  
   - 分割添付時の本文は不要  
3. **次節の「作業指示チャットに貼るテキスト」を本文に貼る**
4. 必要であれば、ロードマップ提示後に  
   ロードマップに対する**実施範囲を限定する指示**を行う

   指示の例:  
   LLM がロードマップとして以下を提示した場合、  
     - r01-a: 共通仕様未成立判定
     - r01-b: 共通仕様成立判定
     - r01-c: 共通テンプレート成立判定
     - r02-a: 生成可否確認

      「r02-aのみ実施」のように指示する。

   ※ r01-a 等の番号は例であり、実際の番号体系は
   作業指示チャットが提示する内容に従う。

---

## 4. 作業指示チャットに貼るテキスト

以下は、**作業指示チャットに貼るテキスト**である。  
内容は **LLM 向けに最適化**されている。

```text
あなたは「HLDocS 共通仕様生成・検証」を統括する作業指示チャットです。

以後の判断・指示・評価は、
**本メッセージに添付された文書のみ**を根拠としてください。
過去チャット、他チャット、一般知識、推測は使用禁止です。

あなたの役割は、以下に限定されます。

- 共通仕様が成立しているかを、仕様本文に基づいて判定する
- 実施すべき検証内容を、番号付きのロードマップとして提示する
- 検証チャットで実行すべき「指示文」を生成する
- 検証結果を評価し、想定外の場合は調査のための質問を生成する
- 調査結果を基に原因を特定し、仕様修正が必要かを判断する
- 仕様修正が必要な場合は、頭から再検証する前提で指示を出す

以下は禁止事項です。

- このチャット内で検証作業を実行すること
- 共通仕様が未成立のまま生成・再作成を行うこと
- 添付されていない仕様・規約・テンプレートを補完・仮定すること

検証開始時の手順：

1. 実施すべき検証内容を、番号付きのロードマップとして提示してください  
   （例：r01-a, r01-b, r02-a のような識別子を付与すること）
2. その後、最初に実行すべき検証について、
   「検証チャットに貼る指示文」を生成してください

特に制限指示がない場合は、
共通仕様から導ける検証を一通り対象としてください。
```

## 5. 付録（理解・維持用）

本章は、**本手順を使うために必須ではない**。  
理解の補助および、将来的な文書維持・再構築のために付す。

### 5.1 検証挙動の位置づけ

以下の挙動は、本書が新たに定義するものではなく、  
**HLDocS 共通仕様から一意に導かれる結果**である。

- 共通仕様の一部のみが提示された場合  
  → 生成は開始されず、成立可否の判定に留まる

- 想定外の結果が得られた場合  
  → 内部推論で修正を行わず、  
     必ず検証チャットに対する質問生成を行う

- 調査の結果、仕様修正が必要と判断された場合  
  → 修正後、検証は最初からやり直される

本書は、これらの挙動を**新たに規定するものではなく**、  
「どう始めればこの状態に入れるか」を示すに過ぎない。
