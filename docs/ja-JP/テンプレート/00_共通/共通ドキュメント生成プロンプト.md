# 共通ドキュメント生成プロンプト

本プロンプトは、  
**利用者の明示指示に基づき、HLDocS 準拠ドキュメントを生成または再作成するための  
document_type 非依存・共通生成プロンプト**である。

本プロンプトは本文内容を規定しない。  
**添付された共通ドキュメントテンプレートを唯一の構造的正とし、  
LLM が行うべき前提検証・処理順序・生成制約・内部自己検査のみ**を定義する。

---

## 0. 最上位生成規則（FAIL-FAST / MUST）

以下のいずれかを満たさない場合、**生成してはならない**。

- document_type が **明示的に指定・合意**されていること
- 生成対象 document_type に対応する  
  - 共通ドキュメントテンプレート  
  - document_type 別テンプレート（必要な場合）  
  - document_type 別生成プロンプト（必要な場合）  
  が **すべて提示**されていること
- 生成モード（`meta` / `apply`）が **明示指定**されていること
- `operation`（`new` / `recreate` / `patch`）が **明示指定**されていること

不足がある場合は、不足内容を列挙して提示を要求し、  
**一切の成果物を出力してはならない**。

出力は **最終成果物のみ**とし、  
思考過程・判断理由・内部検査結果を出力してはならない。

---

## 1. 構造に関する前提（MUST）

- ドキュメント構造は **添付された共通ドキュメントテンプレートの内容をそのまま維持**すること
- 本プロンプトは  
  - 構造要素の列挙  
  - 構造順序の再定義  
  - 構造の補完・省略・再解釈  
  を行わない
- テンプレートに存在しない要素を **追加してはならない**
- テンプレートに存在する要素を **削除・統合・分割してはならない**

構造の正当性判断は、常に **テンプレートとの完全一致**で行う。

---

## 2. LLM-MANAGED 値決定規則（MUST）

### 2.1 doc_id

- 新規生成（`operation = new`）の場合のみ生成を許可する  
  形式：`doc-YYYYMMDD-HHMMSSZ-XXXX`
  - タイムゾーン：UTC
  - `XXXX`：4 桁 base36
- 再作成・差し替え（`operation = recreate` / `patch`）の場合は  
  **既存の doc_id を必ず維持**する
- doc_id を再生成・補正・意味的に変更してはならない

### 2.2 lang

- 明示指定がない場合は `ja-JP`

### 2.3 document_type

- **外部から明示的に合意された値のみ**を使用する
- 未合意の場合は生成してはならない
- 名称や意味から document_type を推測してはならない

### 2.4 canonical_document

- 正規成果物は `true`
- 下書き・検討用等は `false`
- transport の指定によって意味を上書きしてはならない

### 2.5 transport

- 明示指定がある場合のみ使用する
- 指定順・指定内容を **変更してはならない**
- 既定値を暗黙に補完してはならない

---

## 3. 生成モードに関する前提（MUST）

生成は必ず以下いずれかのモードで行う。

### 3.1 meta

- HLDocS 自身（仕様・テンプレート・生成プロンプト）を対象とする生成
- 規約・テンプレート・生成ルールそのものを変更し得る高リスク操作

### 3.2 apply

- HLDocS を **適用して他のドキュメントを生成・再作成**する通常利用
- 既存の HLDocS 規約・テンプレート・生成ルールは前提として不変

モード未指定の場合は **必ず生成を停止**する。

---

## 4. 再作成（差し替え）時の前提（MUST）

`operation = recreate` の場合：

- 利用者は **差し替え対象となる正本全文**を入力として与えなければならない
- LLM は以下を行ってはならない  
  - 要約  
  - 再構成  
  - 表現整理  
  - 推測による補完  
  - 意味的同一性判断による削除
- 利用者が **明示的に指示した変更点のみ**を反映すること

---

## 5. 識別子・参照規約（MUST）

- sec_id / ref_id の生成・使用は **Traceability 規約**に従う
- 意味語・章名・用途語を含めてはならない
- 推測生成・自動補完を行ってはならない
- 記載形式・用途は規約で許可された範囲に限定する

---

## 6. 生成処理ステップ（内部処理・MUST）

LLM は以下の順序でのみ処理を行う。

### Phase 0: 前提検証（FAIL-FAST）
- 0章の最上位生成規則をすべて満たしているか確認

### Phase 1: テンプレート読込
- 共通ドキュメントテンプレートを **構造正本**として読込
- document_type 別テンプレートがある場合は併せて読込

### Phase 2: テンプレート合成
- 共通テンプレートの指定スロットに本文テンプレートを **無加工で差し込む**
- この時点では本文を生成しない

### Phase 3: 本文生成
- 合成済みテンプレートに従い本文を生成
- `operation = recreate` の場合は正本を基準とし、明示変更点のみ反映

### Phase 4: 構造実体化
- テンプレート内の構造トークンを実体表現に変換
- 構造・順序・要素数を変更してはならない

### Phase 5: 内部自己検査（非出力）
- テンプレートとの完全一致
- doc_id 維持／生成ルール遵守
- モード・operation 指定の有無
- 推測生成が行われていないこと
- 規約違反がないこと

### Phase 6: 出力
- Phase 5 をすべて満たした場合のみ最終成果物を出力

---

## 7. ui_copy 出力規則（MUST）

transport に `ui_copy` が指定された場合：

- 出力は **単一のコードブロックのみ**
- コードブロック外に一切の文字列を出力してはならない
- Markdown 全文は **round-trip 復元可能**でなければならない
- 本文中のコードフェンス・構造表現を改変してはならない

---

## 8. 禁止事項（MUST NOT）

- 規約・構造・処理手順の説明
- 編集指示・差分説明・判断理由の出力
- 内部検査内容の出力
- 暗黙の既定値補完
