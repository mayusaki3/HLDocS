# 共通ドキュメント生成プロンプト

本プロンプトは、利用者の明示指示に基づき、HLDocS 準拠ドキュメントを生成または再作成するための
document_type 非依存・共通生成プロンプトである。

本プロンプトは本文内容（ドメイン内容）を規定しない。
添付された共通ドキュメントテンプレートを唯一の構造的正とし、
LLM が行うべき前提検証・処理順序・生成制約・内部自己検査・出力規則のみを定義する。

---

## 0. 最上位生成規則（FAIL-FAST / MUST）

以下のいずれかを満たさない場合、生成してはならない。

- 生成モード（`meta` / `apply`）が明示指定されていること
- `operation`（`new` / `recreate` / `patch`）が明示指定されていること
- document_type が明示的に指定・合意されていること
- 共通ドキュメントテンプレートが提示されていること
- document_type が本文テンプレートを要求する型である場合に限り、document_type 別テンプレートが提示されていること
- document_type 別生成プロンプトが必要な場合、当該プロンプトが提示されていること
- `operation = recreate` / `patch` の場合、差し替え対象となる正本全文が提示されていること
- transport が明示指定されている場合、許可された transport 値であること

不足がある場合は、不足内容を列挙して提示を要求し、一切の成果物を出力してはならない。

出力は最終成果物のみとし、思考過程・判断理由・内部検査結果・差分説明を出力してはならない。

---

## 1. 構造に関する前提（MUST）

- ドキュメント構造は、提示された共通ドキュメントテンプレートの内容をそのまま維持すること
- 本プロンプトは、構造要素の列挙、構造順序の再定義、構造の補完・省略・再解釈を行わない
- テンプレートに存在しない要素を追加してはならない
- テンプレートに存在する要素を削除・統合・分割してはならない
- 構造の正当性判断は、常にテンプレートとの完全一致で行う

---

## 2. LLM-MANAGED 値決定規則（MUST）

### 2.1 doc_id

- `operation = new` の場合のみ新規生成を許可する  
  形式：`doc-YYYYMMDD-HHMMSSZ-XXXX`（UTC 固定、`XXXX` は 4 桁 base36）
- `operation = recreate` / `patch` の場合は既存の doc_id を必ず維持する
- doc_id を再生成・補正・意味的に変更してはならない

### 2.2 lang

- 明示指定がない場合は `ja-JP`

### 2.3 canonical_title

- 明示指定がない場合は、テンプレートおよび正本（recreate/patch 時の入力）に整合する範囲で決定する
- recreate/patch では、正本に存在する canonical_title を維持する

### 2.4 document_type

- 外部から明示的に合意された値のみを使用する
- 未合意の場合は生成してはならない
- 名称や意味から document_type を推測してはならない

### 2.5 canonical_document

- 正規成果物は `true`
- 下書き・検討用等は `false`
- transport の指定によって意味を上書きしてはならない

### 2.6 transport

- 明示指定がある場合のみ使用する
- 指定順・指定内容を変更してはならない
- 既定値を暗黙に補完してはならない

---

## 3. 生成モードに関する前提（MUST）

生成は必ず以下いずれかのモードで行う。

### 3.1 meta

- HLDocS 自身（仕様・テンプレート・生成プロンプト）を対象とする生成
- 規約・テンプレート・生成ルールそのものを変更し得る高リスク操作
- 生成判断の根拠として参照する情報は、利用者から与えられた仕様・テンプレート・生成プロンプト等の設計資料一式に限定されなければならない

### 3.2 apply

- HLDocS を適用して他のドキュメントを生成・再作成する通常利用
- HLDocS 規約・テンプレート・生成ルールは前提として不変でなければならない
- 生成判断の根拠として参照する情報は、共通テンプレート／document_type 別テンプレート／生成プロンプトのみに限定されなければならない

モード未指定の場合は必ず生成を停止する。

---

## 4. operation に関する前提（MUST）

### 4.1 new

- 新規生成である
- doc_id を新規生成してよい（2.1 の範囲のみ）

### 4.2 recreate

- 既存正本を差し替える再作成である
- 利用者は差し替え対象となる正本全文を入力として与えなければならない
- LLM は以下を行ってはならない  
  - 要約
  - 再構成
  - 表現整理
  - 推測による補完
  - 意味的同一性判断による削除
- 利用者が明示的に指示した変更点のみを反映しなければならない
- doc_id、階層リンク行、構造順序などの不変条件を維持しなければならない

### 4.3 patch

- 既存正本に対する部分修正である
- 利用者は差し替え対象となる正本全文を入力として与えなければならない
- LLM は、利用者が明示した差分指示の範囲のみを変更してよい
- それ以外は recreate と同等の不変条件・禁止事項を適用する

---

## 5. 識別子・参照規約（MUST）

- sec_id / ref_id の生成・使用は Traceability 規約に従う
- 意味語・章名・用途語を含めてはならない
- 推測生成・自動補完を行ってはならない
- 記載形式・用途は規約で許可された範囲に限定する

---

## 6. 生成処理ステップ（内部処理・MUST）

LLM は以下の順序でのみ処理を行う。順序を変更してはならない。

### Phase 0: 前提検証（FAIL-FAST）
- 0章の最上位生成規則をすべて満たしているか確認する
- 不足がある場合は不足内容のみを列挙して提示を要求し、成果物を出力してはならない

### Phase 1: テンプレート抽出
- 共通ドキュメントテンプレートから `__COMMON_TEMPLATE_BEGIN__` ～ `__COMMON_TEMPLATE_END__` を抽出する
- document_type 別テンプレートがある場合は `__BODY_TEMPLATE_BEGIN__` ～ `__BODY_TEMPLATE_END__` を抽出する
- 上記マーカーが欠落している、または複数存在する場合、生成および合成を行ってはならない

### Phase 2: テンプレート合成
- 共通テンプレートの指定スロットに本文テンプレートを無加工で差し込む
- この時点では本文を生成してはならない
- この時点では構造トークンを解釈・変換してはならない

### Phase 3: 本文生成および Traceability 構築
- 合成済みテンプレートに従い本文（可変スロット）を生成する
- sec_id / ref_id を Traceability 規約に従って構築・配置する
- `operation = recreate` / `patch` の場合は正本を基準とし、明示変更点のみ反映する
- テンプレート構造、固定マーカー、構造トークンを改変してはならない

### Phase 4: 構造トークン実体化
- テンプレート内の構造トークンを最終表現へ意味等価に置換する
- 構造・順序・要素数を変更してはならない
- 追加・削除・並び替え・要約を行ってはならない

### Phase 5: Transport Encoding 適用
- transport が明示指定されている場合、Transport Encoding 規約に従い出力形式を適用する
- transport によって文書の意味・構造・識別子を変更してはならない

### Phase 6: 最終検証（非出力）
- テンプレートとの完全一致（構造・固定要素・順序）を検査する
- doc_id / 階層リンク行 / 構造順序等の不変条件が保持されていることを検査する
- 推測生成が行われていないことを検査する
- transport が指定されている場合、Transport Encoding 規約に定める出力制約に適合していることを検査する
- 検査結果・内部ログを出力してはならない

### Phase 7: 出力
- Phase 6 をすべて満たした場合のみ最終成果物を出力する
- 最終成果物以外（検証結果・中間生成物・理由・差分説明）を出力してはならない
- 出力時に文書内容・構造・識別子を改変してはならない

---

## 7. ui_copy 出力規則（MUST）

transport に `ui_copy` が指定された場合：

- 出力は単一のコードブロックのみ
- コードブロック外に一切の文字列を出力してはならない
- Markdown 全文は round-trip 復元可能でなければならない
- 本文中のコードフェンス・構造表現を改変してはならない

---

## 8. 禁止事項（MUST NOT）

- 規約・構造・処理手順の説明の出力
- 編集指示・差分説明・判断理由の出力
- 内部検査内容の出力
- 暗黙の既定値補完
- テンプレート・規約の再解釈・補完・要約
- LLM-MANAGED メタデータ領域の侵害
