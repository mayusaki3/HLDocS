# 共通ドキュメント生成プロンプト

本プロンプトは、利用者の明示指示に基づき、HLDocS 準拠ドキュメントを生成または再作成するための  
document_type 非依存・共通生成プロンプトである。

本プロンプトは本文内容（ドメイン内容）を規定しない。  
提示された共通ドキュメントテンプレートを唯一の構造的正とし、  
LLM が行うべき前提検証・処理順序・生成制約・内部自己検査・出力規則のみを定義する。

---

## 0. 最上位生成規則（FAIL-FAST / MUST）

以下のすべてを満たさない場合、生成してはならない。

- 生成モード（ENUM：`meta` / `apply`）が明示指定されていること
- `operation`（ENUM：`new` / `recreate` / `patch`）が明示指定されていること
- document_type が明示的に指定・合意されていること
- 共通ドキュメントテンプレートが提示されていること
- document_type 別テンプレートを要求する型である場合に限り、document_type 別テンプレートが提示されていること
- document_type 別生成プロンプトが必要な場合、当該プロンプトが提示されていること
- `operation = recreate` / `patch` の場合、差し替え対象となる正本全文が提示されていること
- transport（ENUM：`ui_copy` / `download` / `true_out`）が明示指定されている場合、許可 ENUM 値であること

不足がある場合は、不足内容を列挙して提示を要求し、一切の成果物を出力してはならない。

出力は最終成果物のみとし、思考過程・判断理由・内部検査結果・差分説明を出力してはならない。

---

## 1. 共通構造命令（MUST）

生成されるドキュメントは、  
**共通ドキュメントテンプレートに定義された構造を完全一致で維持**しなければならない。

LLM は以下を行ってはならない。

- 共通ドキュメントテンプレートに定義されていない構造要素の追加
- 構造順序の変更
- 空行数・区切り・再掲位置の変更
- テンプレート構造を説明文として再解釈すること

---

## 2. LLM-MANAGED 値決定規則（MUST）

### 2.1 doc_id

- 新規生成時は `doc-YYYYMMDD-HHMMSSZ-XXXX` 形式で生成する  
  - タイムゾーン：UTC  
  - XXXX：4 桁 base36
- 再作成・差し替え時は **既存の doc_id を必ず維持**する

### 2.2 lang

- 明示指定がない場合は `ja-JP` とする

### 2.3 document_type

- 許可 ENUM：`spec` / `index` / `template` / `prompt` / `testspec` / `note` / `minutes` / `usage`
- **外部から合意された値のみ**を使用する
- 未合意・未定義値を推測してはならない

### 2.4 canonical_document

- 許可 ENUM：`true` / `false`
- 正規成果物は `true`
- 下書き・検討用等は `false`

---

## 3. 識別子に関する共通規約（MUST）

### 3.1 sec_id

- 形式は `sec_<random>` のみ許可する
- `<random>` は衝突確率が十分低い方式を用いる
- 意味語・章名・番号・用途語・document_type 名を含めてはならない
- 一意性は **(doc_id, sec_id)** の組で成立する
- 生成・確定タイミングは document_type 固有規約に従う

### 3.2 ref_id

- 形式は `ref_<random>` のみ許可する
- 意味語・章名・番号・用途語を含めてはならない
- 一意性は **(doc_id, ref_id)** の組で成立する
- 恒久参照（sec_id）の代替として使用してはならない

---

## 4. 参照形式の共通制約（MUST）

### 4.1 恒久参照

- 許可形式：`doc_id#sec_id`
- 上記形式以外の章・検証単位参照は禁止

### 4.2 派生参照

- 許可形式：`doc_id#ref_id`
- 用途 ENUM：`rationale` / `derivation`
- 派生参照は恒久参照を代替してはならない

---

## 5. hldocs コメント参照表現（MUST）

参照は HTML コメント形式で記載する。

### 5.1 記載形式

恒久参照：
```
<!-- hldocs:ref=doc-XXXXXXXX-XXXX#sec_xxxx -->
```

派生参照：
```
<!-- hldocs:ref=doc-XXXXXXXX-XXXX#ref_yyyy hldocs:rel=rationale -->
```
```
<!-- hldocs:ref=doc-XXXXXXXX-XXXX#ref_yyyy hldocs:rel=derivation -->
```

### 5.2 制約

- `hldocs:rel` は派生参照時のみ使用する
- `hldocs:rel` は `hldocs:ref` と同一コメント内に記載する
- 恒久参照に `hldocs:rel` を付与してはならない

---

## 6. Transport Encoding 適用規則（MUST）

### 6.1 ui_copy

transport が `ui_copy` の場合、以下を **絶対規則**とする。

- 出力は **単一のコードブロックのみ**
- コードブロック外に文字列を出力してはならない
- 本文中に出現する連続バッククォート最大数を `M` とする
- 外側コードフェンス数 `N = M + 1`
- 本文中にバッククォートが存在しない場合は `N = 3`
- 外側フェンス行にはフェンス記号のみを記載し、言語指定を付与してはならない
- コードブロック内には **復元可能（roundtrip）な Markdown 全文**を格納する

---

## 7. 再作成（差し替え）時の不変条件（MUST）

`operation` が `recreate` / `patch` の場合、以下を不変条件として保持する。

- doc_id
- canonical_title
- document_type
- 文書構造順序
- 階層リンク行（先頭・末尾とも完全一致）

不足情報を推測・補完してはならない。

---

## 8. 内部自己検査（非出力・MUST）

以下を内部で必ず検査し、すべて合格した場合のみ出力する。

- 共通ドキュメントテンプレート構造との完全一致
- doc_id / sec_id / ref_id 形式の妥当性
- (doc_id, sec_id) / (doc_id, ref_id) の一意性成立
- 参照形式・hldocs コメントの整合性
- document_type が許可 ENUM 内であること
- 推測生成を行っていないこと
- 生成結果の本文中に、作業指示・省略表現・参照注釈等の成果物として無効な記述が含まれていないこと
- ui_copy 外側コードフェンス規則を満たしていること

検査結果は一切出力してはならない。

---

## 9. document_type 固有規則（内部）

document_type 固有の判断・制約は、  
別途与えられる document_type 別生成プロンプトを内部適用する。

それらを本文に出力してはならない。
