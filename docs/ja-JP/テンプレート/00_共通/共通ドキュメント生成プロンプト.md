# 共通ドキュメント生成プロンプト

本プロンプトは、HLDocS 管理下ドキュメントを生成するための **共通生成プロンプト**である。  
document_type に依存しない **命令・判断規則・自己検査**を定義する。

---

## 0. 最上位命令（MUST）

- document_type または使用テンプレートが合意されていない場合、生成してはならない。
- 上記の場合、必ず問い合わせを行い、合意が得られるまで出力してはならない。
- 出力は最終成果物のみとする。
- 思考過程・判断理由・検査結果は一切出力してはならない。
- HLDocS 前提条件・共通規約は内面化して振る舞うが、本文に再掲してはならない。

---

## 1. 共通構造命令（MUST）

生成物は、必ず以下の構造を順序どおり満たさなければならない。

1. LLM-MANAGED ブロック
2. 空行 1 行
3. 階層リンク行
4. 空行 1 行
5. 本文
6. 空行 1 行
7. 区切り線
8. 空行 1 行
9. 先頭と完全一致する階層リンク行（再掲）

---

## 2. LLM-MANAGED 値決定規則（MUST）

### 2.1 doc_id

- 新規生成時は `doc-YYYYMMDD-HHMMSSZ-XXXX`（UTC / base36 4 桁）で生成する。
- 更新・再作成時は既存の doc_id を必ず維持する。

### 2.2 lang

- 指定がない場合は ja-JP とする。

### 2.3 document_type

- 外部から合意された値を使用する。
- 未合意の場合は必ず問い合わせを行い、生成してはならない。
- document_type 名称の意味から生成規則を推測してはならない。
- 当該 document_type の具体的な責務・禁止事項は、合意された仕様・テンプレート・生成プロンプトで規定される。

### 2.4 canonical_document

- 正規成果物は true。
- 下書き・検討用などの場合は false。

### 2.5 transport

- 既定値は [true_out]。
- UI コピー用途が指定された場合は [ui_copy] を使用する。
- ファイル回収が必要な場合は download を含める。
- transport の指定によって canonical_document の意味を上書きしてはならない。

---

## 3. ui_copy 専用規則（MUST）

transport に ui_copy が指定された場合、以下は絶対規則である。

### 3.1 出力形式

- 出力は単一のコードブロックのみとする。
- コードブロック外に一切の文字列を出力してはならない。
- コードブロック内には、復元可能（roundtrip）な Markdown 全文を格納する。

### 3.2 UI 破壊要因の回避（MUST）

- UI が破壊しやすい要素（コードブロック、引用、複雑なインデントなど）が本文に必要な場合でも、削除してはならない。
- UI 安全化のために必要な場合は、ui_copy の責務として
  **提示用の等価表現に変換してよい**。
- ただし、構造・意味・情報量は完全に保持されなければならず、
  削除・要約・文章化・意味改変を行ってはならない（MUST NOT）。
- 変換後も、構造・意味・論理階層が一致し、後処理で復元可能でなければならない。
- 文章による置換（意味改変・説明化）を行ってはならない。

---

## 4. 禁止事項（MUST NOT）

- 規約・構造・生成方法・判断基準の説明
- 編集指示・作業指示・差分説明
- チェックリスト・検査結果・修正理由

---

## 5. 内部自己検査（非出力・MUST）

以下を必ず内部で検査し、すべて合格した場合のみ出力する。

- 構造完全性（LLM-MANAGED / 階層リンク再掲 / 順序）
- 値域妥当性（doc_id 形式 / transport 配列 / document_type 合意済み）
- ui_copy 指定時の出力形式遵守
- UI 破壊要因の削除・説明化が行われていないこと
- 前提・規約・作業文が本文に混入していないこと

不合格の場合は修正・再生成を行い、合格時のみ最終成果物を出力する。

---

## 6. document_type 固有規則（内部）

- document_type 固有の判断・検査・制約は別プロンプトとして内部適用する。
- それらを本文に出力してはならない。
