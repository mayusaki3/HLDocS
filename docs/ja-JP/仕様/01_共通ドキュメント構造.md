# 共通ドキュメント構造

## 1. 目的

- 人間と LLM が同一の Markdown フォーマットでドキュメントを扱えるようにする
- 構造・同一性を LLM が保証し、人間は内容判断に集中できるようにする
- ツール化（リンク検証・パス再構築・名称変更）に耐える構造を提供する

---

## 2. 基本構造

各ドキュメントは以下の構造を持つ。

1. LLM 管理下ブロック（必須）
2. 階層リンク行（先頭）
3. タイトル
4. 本文
5. 区切り線（---）
6. 階層リンク行（末尾）

---

## 3. LLM 管理下ブロック

- ドキュメント先頭に配置する
- BEGIN/END の省略形として、HTML コメント形式を用いる
- 内容は LLM のみが編集することを前提とする

### 必須項目

- doc_id：ドキュメントの論理的識別子（全体で一意・不変）
- lang：ドキュメントの言語（例：ja-JP）
- canonical_title：正規タイトル
- document_type：spec / index / manual / template-material 等
- output_mode
- transport

---

## 4. 階層リンク行

- ドキュメントの論理階層を「上位 > … > 自身」の形式で表す
- 先頭と末尾の両方に記載する
- 表示用であり、リンク記法を使用してよい（任意）。
  - 初期状態ではリンクを含まなくてもよい
  - 後続ツールによりリンクを補完してよい

### 例

- `HLDocS ドキュメント目次 > 仕様 > 共通ドキュメント構造`

---

## 5. 目次ドキュメント

- 目次.md も doc_id を持つ
- 目次.md も階層リンク行を持つ
- 目次は最上位ノードであるため、階層リンク行は自身のタイトルのみとする

例：

- `HLDocS ドキュメント目次`

---

## 6. リンク必須／不要の区別

### リンク必須（逆方向リンクを持つ）

- 仕様
- 使い方
- ガイド
- その他、ドキュメント体系の一部を構成する文書

### 正方向リンクのみ必要（逆方向リンク不要）

- テンプレート
- プロンプト
- ドキュメント生成素材

※ これらは目次から参照可能であれば十分とする。

---

## 7. doc_id の生成と扱い

- 新規作成時：LLM が一意な doc_id を生成する
- 既存文書の更新時：doc_id は絶対に変更しない
- doc_id 文字列自体には言語情報を含めない
- 言語は lang フィールドで管理する
