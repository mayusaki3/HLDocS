# HLDocS 前提条件

本書は、HLDocS における **すべての仕様・テンプレート・生成プロンプトが成立するための固定前提** を定義する。  
本書に記載された内容は、個別仕様によって上書き・緩和・解釈変更されてはならない。

---

## 1. 基本前提（MUST）

### 1.1 LLM の認識前提

- LLM は、本書および各仕様書の本文内容を **事前知識として保持していない**。
- LLM は、過去の会話文脈が保持されていることを前提としてはならない。
- 各ドキュメント生成・再生成は、**単体で完結し、再現可能**でなければならない。

### 1.2 仕様提示モデル

- LLM に与えられる入力は、  
  **共通テンプレート／document_type 別テンプレート** および  
  **共通生成プロンプト／document_type 別生成プロンプト** の組み合わせである。
- 合成は必須条件ではなく、生成段階や目的に応じて省略され得る。
- HLDocS の各仕様本文は、  
  **HLDocS 自身の仕様改定・検証を行う場合を除き**、  
  LLM に対する判断材料として与えられない。

---

## 2. HLDocS 不変条件（MUST）

### 2.1 構造不変条件

- すべての HLDocS 管理下ドキュメントは、共通ドキュメント構造に従う。
- LLM-MANAGED ブロックは、必ずドキュメント先頭に配置される。
- 階層リンク行は、先頭および末尾に **同一内容** で再掲される。

### 2.2 同一性不変条件

- ドキュメントの論理的同一性は `doc_id` によってのみ識別される。
- ファイル名、パス、番号、言語、本文内容、見出し構造は  
  **同一性の判断材料とならない**。

---

## 3. LLM-MANAGED 管理原則（MUST）

### 3.1 管理責務

- LLM-MANAGED ブロック内の値は、**LLM のみが決定・更新する**。
- 人間による直接編集は、原則としてドキュメント同一性を破壊する行為とみなされる。

#### 例外（MAY）

以下の場合に限り、人間が `doc_id` を削除または無効化する行為を許容する。

- 明示的なドキュメント分割を行い、新規ドキュメントとして再生成する場合
- 明示的な置換・廃止を行い、同一性の継承を行わない場合

これらの場合でも、**既存の doc_id を再利用してはならない**。

---

## 4. document_type と役割モデル（MUST）

- document_type は ENUM として扱われる。
- document_type の変更は、論理的同一性の変更を意味しない。
- document_type は、構造・判断ロジック・生成順序を直接規定しない。

### 4.1 他仕様との関係

- document_type に関する詳細なキー定義および編集規約は、  
  [**LLM-MANAGED ブロック規約**](./04_LLM-MANAGEDブロック規約.md) に従う。
- 本章は、それらを束ねる **前提モデルの宣言** であり、  
  個別仕様の内容を上書きしない。

### 4.2 document_type: template の責務（MUST）

- template は、HLDocS 管理下ドキュメントの **構造（骨格）** を定義する。
- template は、判断ロジック・条件分岐・検査手順・出力方式の選択規則を  
  **含めてはならない（MUST NOT）**。
- template は、共通テンプレートおよび document_type 別テンプレートとして提供され得る。
- template の意味・役割は、名称から推測してはならず、  
  仕様および生成プロンプトにより規定される。

### 4.3 document_type: prompt の責務（MUST）

- prompt は、LLM の **判断・振る舞い・内部自己検査** を規定する。
- prompt は、構造（骨格）を規定してはならない（MUST NOT）。
- prompt は、共通生成プロンプトおよび document_type 別生成プロンプトとして提供され得る。
- prompt の意味・役割は、名称から推測してはならず、  
  仕様および生成プロンプトにより規定される。

---

## 5. 前提変更に関する注意（IMPORTANT）

- 本書に記載された前提条件を変更する場合、  
  それは HLDocS の **世代（generation）が変わること** を意味する。
- 世代情報は、本ドキュメント体系とは独立した  
  **HLDocS 管理外ファイル** として管理する。

### 5.1 世代・バージョン管理方針

- 世代・バージョン情報は、`docs` フォルダと同階層に配置してよい。
- 当該ファイルは HLDocS 管理対象外とし、LLM-MANAGED ブロックを持たない。
- 具体的な形式・命名規則は、本書では規定しない。
