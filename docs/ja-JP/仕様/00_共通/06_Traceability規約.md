# Traceability（仕様・テスト・コード紐づけ）規約

本書は、HLDocS において  
**仕様（spec）・テスト仕様（testspec 等）・ソースコード間の対応関係**  
を安定的かつ再構成可能な形で管理・検証するための共通規約を定義する。

---

## 1. Purpose（存在理由）

本規約は以下を目的とする。

- 仕様・テスト・コード間の対応関係を **恒久的に識別**できるようにする  
- ファイル移動・名称変更に耐える **安定した紐づけ**を提供する  
- 人間と LLM の双方が同一情報を用いて **整合性確認**を行えるようにする  

---

## 2. Non-goals（対象外）

本規約は以下を目的としない。

- ソースコードの自動生成・自動修正  
- テストケース設計方法そのものの定義  
- トレーサビリティ情報の自動補完  
- sec_id の採番アルゴリズムの詳細定義  

---

## 3. 基本原則

- **文書単位の同一性**は `doc_id` により保証する  
- **検証単位の同一性**は `sec_id` により表現する  
- 一意性は **`(doc_id, sec_id)` の組**によって成立する  
- 人間向け可読情報と、機械向け識別情報を明確に分離する  
- 紐づけ情報は **本文の意味や構造に影響しない形式**で付与する  

---

## 4. 章単位識別子（sec_id）

### 4.1 定義

`sec_id` は、ドキュメント内の特定の章・節・検証観点を識別する  
**検証単位識別子**である。

`sec_id` は単体でのグローバル一意性を要求しない。  
**`doc_id` と組み合わせることで一意性を持つ**ものとする。

### 4.2 意味論

`sec_id` は以下を示す。

- ある仕様上の要求・振る舞いが、どのテスト仕様によって検証されるか  
- あるテスト仕様が、どの仕様上の要求・振る舞いを検証しているか  

すなわち `sec_id` は、  
**traceability を構成する検証単位キー**である。

### 4.3 確定原則（重要）

- `sec_id` は **testspec を起点として確定する**  
- spec 単体の作成時点では `sec_id` を付与してはならない  
- 対応する testspec が存在しない `sec_id` は定義してはならない  

この原則は、新規作成・再作成・既存文書の再構成のいずれにも適用される。

### 4.4 役割分担

- testspec  
  - 検証観点ごとに `sec_id` を **初出・確定**させる主体  
- spec  
  - testspec により確定した `sec_id` を **後追いで受け取る主体**  
  - 推測・自動生成によって `sec_id` を付与してはならない  

### 4.5 許可・禁止事項

**許可**

- testspec 新規作成時に検証単位として `sec_id` を定義すること  
- 規格外テスト仕様を HLDocS 準拠に再作成する際に `sec_id` を付与すること  
- spec に `sec_id` が存在しない状態で、testspec 側に正式な `sec_id` を付与すること  

**禁止**

- spec 生成時に testspec 参照なしで `sec_id` を付与すること  
- LLM の推測のみで `sec_id` を生成・付与すること  
- `sec_id` を traceability 以外の目的（装飾、進捗管理、履歴管理等）で使用すること  

---

## 5. sec_id の付与方法

### 5.1 記載形式

`sec_id` は、対象となる章見出し直下に **HTML コメントとして記載**する。

#### 記載例

```markdown
## 3. 認証トークンの失効
<!-- hldocs:sec_id=spc_9f3a7c2e -->
```

### 5.2 制約

- 一度確定した `sec_id` は **変更してはならない**  
- 人間可読性は要求しない  
- 同一文書内で重複してはならない  

---

## 6. 章単位参照（ref）

### 6.1 恒久参照形式

恒久的な章単位参照は、以下の形式 **のみ**を使用する。

`doc_id#sec_id`

上記以外の形式による参照指定表現  
（章名・節名・位置情報・暫定識別子等を含む）は、  
**定義されず、かつ生成・使用してはならない**。

#### 表記例

```text
doc-20260120-000000Z-SPC1#spc_9f3a7c2e
```

---

## 7. パスリンク行

### 7.1 基本方針

- 人間が直接開ける **Markdown リンク**を使用する  
- 機械的同一性は **HTML コメント**で保持する  

### 7.2 規定形式

```markdown
- [認証トークンの失効](../../仕様/auth/session.md)
  <!-- hldocs:ref=doc-20260120-000000Z-SPC1#spc_9f3a7c2e -->
```

---

## 8. ソースコード側の紐づけ

### 8.1 タグ形式

```text
@hldocs.ref doc-20260120-000000Z-SPC1#spc_9f3a7c2e
```

### 8.2 制約

- 複数指定可  
- 順序は問わない  
- 言語固有のコメント規約に従うこと  

---

## 9. 移行・再構成時の補足規定

再構成・移行作業に限り、  
一時的に spec / testspec に付与された `sec_id` をすべて除去し、  
再付与することを許容する。

この操作は traceability 再構築を目的とする場合に限り、  
恒久成果物公開前に完了していなければならない。

---

## 10. LLM による整合性確認時の振る舞い

### 10.1 許可される動作

- `doc_id#sec_id` の実在確認  
- spec / testspec / コード間の対応確認  
- 未参照章・孤立参照の検出  
- 不整合箇所の指摘・列挙  

### 10.2 禁止される動作

- `sec_id` の新規生成・変更  
- spec / testspec / コードの自動修正  
- コメントの自動追加・削除  
- `doc_id#sec_id` 以外の参照指定表現を生成・使用すること  

---

## 11. 内部自己検査（非出力）

- `sec_id` が HTML コメントとして記載されていること  
- 一意性が `(doc_id, sec_id)` で成立していること  
- 恒久参照形式のみが使用されていること  
- 生成・修正指示が含まれていないこと
