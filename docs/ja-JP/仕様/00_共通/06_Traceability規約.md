# Traceability（仕様・テスト・コード紐づけ）規約

本書は、HLDocS において  
**仕様（spec）・テスト仕様（testspec 等）・ソースコード間の対応関係**
を安定的に管理・検証するための共通規約を定義する。

---

## 1. Purpose（存在理由）

本規約は以下を目的とする。

- 仕様・テスト・コード間の対応関係を **恒久的に識別**できるようにする
- ファイル移動・名称変更に耐える **安定した紐づけ**を提供する
- 人間と LLM の双方が同一情報を用いて **整合性確認**を行えるようにする

---

## 2. Non-goals（対象外）

本規約は以下を目的としない。

- ソースコードの自動生成・自動修正
- sec_id の自動採番ロジックの定義
- テストケース設計方法の定義
- トレーサビリティ情報の自動補完

---

## 3. 基本原則

- **ファイル単位の同一性**は `doc_id` により保証する
- **章単位の同一性**は `sec_id` により保証する
- 人間向けの可読性と、機械向けの安定性を分離する
- 紐づけ情報は **本文に影響しない形式**で付与する

---

## 4. 章単位識別子（sec_id）

### 4.1 定義

`sec_id` は、ドキュメント内の特定の章・節を一意に識別する  
**章単位の恒久ID**である。

### 4.2 付与方法

- 対象となる章見出しの直下に、HTMLコメントとして記載する
- 例：

```markdown
## 3. 認証トークンの失効
<!-- hldocs:sec_id=spc_9f3a7c2e -->
```

### 4.3 制約

- 一度付与した `sec_id` は **変更してはならない**
- 人間可読性は要求しない
- 重複しない値であれば **乱数でよい**
- 文書内で一意であること

---

## 5. 章単位参照（ref）

### 5.1 参照形式

章単位の参照は、以下の形式で表現する。

```text
doc_id#sec_id
```

例：

```text
doc-20260120-000000Z-SPC1#spc_9f3a7c2e
```

---

## 6. パスリンク行

### 6.1 基本方針

- 人間が直接開ける **Markdownリンク**を使用する
- 機械的な同一性・再構成性は HTML コメントで保持する

### 6.2 規定するリンク行の形

```markdown
参照：
- [認証トークンの失効](../../仕様/auth/session.md)
  <!-- hldocs:ref=doc-20260120-000000Z-SPC1#spc_9f3a7c2e -->
```

### 6.3 意味

- Markdownリンク：人間用（パス依存）
- HTMLコメント：機械用（doc_id + sec_id）

---

## 7. ソースコード側の紐づけタグ

### 7.1 タグ形式

```text
@hldocs.ref doc_id#sec_id
```

### 7.2 例（TypeScript）

```ts
/**
 * @hldocs.ref doc-20260120-000000Z-SPC1#spc_9f3a7c2e
 */
export function revokeAllTokens() { ... }
```

### 7.3 例（Java）

```java
/**
 * @hldocs.ref doc-20260120-000000Z-SPC1#spc_9f3a7c2e
 */
public void revokeAllTokens(...) { ... }
```

### 7.4 制約

- 複数指定可
- 順序は問わない
- 言語固有のコメント規約に従うこと

---

## 8. LLM による整合性確認時の振る舞い

### 8.1 許可される動作

- `@hldocs.ref` が参照する `doc_id#sec_id` の実在確認
- spec / testspec 側に存在する `sec_id` とコード側参照の対応確認
- 未参照章・未実装章・孤立参照の検出
- 不整合箇所の **指摘・列挙**

### 8.2 禁止される動作

- ソースコードの修正・生成
- コメントの自動追加・削除
- sec_id の自動付与
- 実装内容の提案

---

## 9. 他 document_type との関係

- spec：正を宣言する文書
- testspec：検証内容を宣言する文書
- index：紐づけ関係の俯瞰・分類
- prompt：整合性確認手順の定義

---

## 10. 内部自己検査（非出力）

- sec_id が HTML コメントとして記載されていること
- ref が `doc_id#sec_id` 形式であること
- 人間用リンクと機械用情報が分離されていること
- 修正・生成に関する記述が含まれていないこと
