# ドキュメント参照・ナビゲーション規約

## 目的

本規約は、HLDocSにおけるドキュメント間参照、階層リンク、目次、README、多言語切替等のナビゲーションを統一することを目的とする。  
また、LLMによるリンク誤生成や階層誤認識を防止することを目的とする。

---

## 適用範囲

本規約は以下に適用する。

* ドキュメント本文中の参照リンク
* ドキュメント先頭および末尾の階層リンク
* 目次ドキュメント
* README
* 多言語切替リンク
* その他ナビゲーション目的のリンク

---

## 基本原則

### 論理構造と物理構造

論理構造と物理構造は別概念とする。

```text
論理構造
≠
物理構造
```

論理構造とは利用者が閲覧するナビゲーション構造を指す。  
物理構造とはファイルおよびフォルダ構成を指す。

---

### 論理構造優先

ナビゲーション生成時は論理構造を優先しなければならない（MUST）。  
物理構造のみを根拠として論理構造を生成してはならない（MUST NOT）。

論理構造は以下の優先順位で決定する。

1. 利用者が明示した論理構造
2. 利用者が明示した階層リンク
3. 目次ドキュメント
4. フォルダ構造
5. FAIL-FAST

フォルダ構造を使用する場合、親フォルダを論理親として扱う。

例:
```text
A
└ B
  └ C
     └ D.md
```
論理構造 = A > B > C > D

フォルダ内に目次ドキュメントが存在する場合、フォルダ名より目次ドキュメントを優先する。

例:
```text
A
└ B
  └ C
     ├ 目次.md
     └ D.md
```
論理構造 = A > B > C(目次) > D

---

### 目次ドキュメント

目次ドキュメントとは、論理構造を定義するためのドキュメントである。  
利用者が目次として指定したドキュメントを目次ドキュメントとして扱う。

ファイル名は固定しない。

例:

* 目次.md
* 検証目次.md
* API目次.md

---

### 一意性

同一論理階層内において、目次ドキュメント名は一意でなければならない（MUST）。  
また、異なる論理階層間であっても、
同一名称の目次ドキュメントを作成してはならない（MUST NOT）。

例:

NG

```text
仕様
 └ API目次

検証
 └ API目次
```

OK

```text
仕様
 └ API仕様目次

検証
 └ API検証目次
```

目次ドキュメント名が重複する場合、LLM は新規作成を行わず、
利用者へ確認を求めなければならない（MUST）。

---

## ドキュメント参照規則

### 表示名

リンク表示名には論理名称を使用する。  
管理番号を表示してはならない（MUST NOT）。  
ファイル名を表示してはならない（MUST NOT）。

---

### 例:

NG

```markdown
[01_前提条件](./01_前提条件.md)
```

OK

```markdown
[前提条件](./01_前提条件.md)
```

---

NG

```markdown
[01_spec_仕様](./01_spec_仕様.md)
```

OK

```markdown
[仕様](./01_spec_仕様.md)
```

---

## 階層リンク規則

### 形式

階層リンクは以下の形式とする。

```text
[目次](...)
>
[親ドキュメント](...)
>
現在ドキュメント
```

---

### 表示名

階層リンクにも論理名称を使用する。  
管理番号を表示してはならない。  
ファイル名を表示してはならない。

---

### 例:

NG

```text
目次 > 00_共通 > 01_前提条件
```

OK

```text
目次 > 共通 > 前提条件
```

---

## 階層リンク導出規則

### 導出優先順位

階層リンクの導出は以下の優先順位で行う。

1. 利用者が明示した階層リンク
2. 同階層ドキュメントの階層リンク
3. 同ディレクトリの目次ドキュメント
4. 利用者が提示したフォルダ構成
5. FAIL-FAST

---

### 推測禁止事項

論理構造を決定する際、

フォルダ構造の親子関係を利用することは許可される。

ただし、以下から論理名称や論理親子関係を推測してはならない（MUST NOT）。

* フォルダ名の意味
* 管理番号
* ファイル名の意味
* ディレクトリ深さの意味

---

例:

物理構造

```text
90_技術検証
└ P0-2_WebView_技術検証
```

以下の推測は禁止。

```text
技術検証
└ WebView技術検証
```

利用者が論理構造を提示していない場合、LLM は論理名称を推測してはならない。

---

一方、

```text
A
└ B
  └ C
     └ D.md
```

のような構造に対し、

```text
A > B > C > D
```

という親子関係のみを利用することは許可される。

---

## 論理構造の例

### 例1

物理構造

```text
30_検証
├─検証目次.md
├─01_検証1.md
└─02_検証2.md
```

論理構造

```text
目次
└─検証目次
   ├─検証1
   └─検証2
```

階層リンク

```markdown
[目次](../目次.md)
>
[検証目次](./検証目次.md)
>
検証1
```

---

### 例2

物理構造

```text
90_技術検証
└─P0-2_WebView_技術検証
```

論理構造

```text
目次
└─技術検証
   └─WebView技術検証
```

階層リンク

```markdown
[目次](../目次.md)
>
[技術検証](...)
>
WebView技術検証
```

---

## 目次規則

目次は論理構造を表現するものとする。  
フォルダ構成をそのまま表現するものではない。  
目次生成時は論理構造を優先しなければならない。

---

## README規則

READMEは利用者向けの入口ドキュメントとする。  
READMEからは以下へアクセスできることを推奨する。

* 目次
* 利用方法
* 主要仕様
* 多言語切替

---

## 多言語リンク規則

多言語切替リンクは論理名称を使用する。

例:

```markdown
[日本語](./README.md) | [English](./README_en-US.md)
```

---

## FAIL-FAST

論理構造を決定できない場合、LLMは推測してはならない。  
利用者へ確認を求めなければならない（MUST）。

---

## Traceability

本規約は以下へ影響する。

* 共通ドキュメントテンプレート
* 共通ドキュメント生成プロンプト
* index仕様
* README
* 目次
* 全ドキュメントタイプ
