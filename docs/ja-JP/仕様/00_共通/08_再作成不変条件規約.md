# 再作成不変条件規約

本書は、HLDocS において **再作成（recreate）および差し替え（patch）** を行う際に、  
生成処理が必ず保持しなければならない **不変条件**を定義する。

本規約は、文書内容の正しさや意味論を規定するものではなく、  
**同一文書としての連続性を保証するための生成上の拘束条件**を定義する。

本書は、「HLDocS 前提条件」という仕様が参照可能である場合にのみ適用される。
- 「HLDocS 前提条件」が入力として与えられていない場合、  
または当該仕様に基づく適用可否が確定していない場合、  
本書に基づく判断・生成・再作成・工程実行を行ってはならない。
- この場合、許可されるのは、  
提示された文書の受理および存在確認、  
ならびに前提条件が未参照または未確定である旨の通知のみとする。
- 「HLDocS 前提条件」が入力文書一覧に含まれない場合、生成・再作成・成果物提示を一切行ってはならない。

---

## 1. 適用範囲（MUST）

本規約は、以下の operation に適用される。

- recreate
- patch

new に対しては、本規約は適用されない。

---

## 2. 再作成の基本原則（MUST）

再作成（recreate）および patch は、  
**既存の doc_id を保持したまま同一文書を改版する生成行為**である。

したがって、再作成においては以下を満たさなければならない。

- 文書の同一性が保持されること
- 文書識別情報が変化しないこと
- 文書構造の連続性が保持されること

---

## 3. 不変項目（MUST）

再作成（recreate）および patch において、  
以下の項目は **不変条件**として必ず保持しなければならない。

- doc_id  
- canonical_title  
- document_type  
- 文書全体の構造順序  
- 階層リンク行（先頭および末尾）

これらの不変項目は、
再作成対象として明示的に添付された修正前正本を基準として保持しなければならない。

これらの不変項目は、
推測・補完・再解釈・仕様一般化・テンプレート再適用等による変更を行ってはならない。

---

## 4. 再作成時の出力制約（MUST）

再作成（recreate）および patch においては、以下を満たさなければならない。

- 未変更部分を含め **全文を出力**すること  
- 差分説明・参照表現で本文を代替しないこと  
- 「変更なし」「同上」等の省略表現を用いないこと  

---

## 5. 再作成時の入力解釈（共通規則）（MUST）

再作成（recreate）および patch において、LLM は以下を判断根拠として使用してよい。

- 修正前正本（同一 doc_id を持つ文書）
- 明示的に添付された共通仕様
- 明示的に添付されたテンプレート
- 明示的に添付された生成プロンプト

以下を行ってはならない（MUST NOT）。

- 修正前正本以外の旧版・別版文書を参照する  
- 過去会話・暗黙知・一般知識を判断根拠とする  

修正前正本は、**更新対象であると同時に判断根拠として参照可能な入力**として扱われる。

---

## 6. 再作成成立条件（MUST）

再作成（recreate）は、以下の条件をすべて満たす場合にのみ成立する（MUST）。

- 修正前正本の本文実体が入力として提示（provided）されていること  
- 当該正本の doc_id が確定していること  
- canonical_title / document_type が確定していること  
- 不変項目（第3節）が維持可能であること  

指示に「再作成」「改版」「差し替え」「全文差し替え」等の語が含まれる場合は、  
生成フェーズ実行規約の定義済みマッピングに従い、  
operation は recreate（または patch）として解釈する（MUST）。

ただし、修正前正本の本文実体が提示されていない場合、  
再作成（recreate）または patch は成立しない。

この場合、LLM は生成フェーズを開始してはならない（MUST）。  
当該状態は Phase 0 における入力不備として扱い、  
FAIL-FAST としなければならない（MUST）。

修正前正本が提示されていない状態で、  
operation を new に変更して生成を継続してはならない（MUST NOT）。

---

## 7. document_type = prompt における特則（MUST）

document_type が `prompt` の場合に限り、  
再作成（recreate）および patch において以下の特則を適用する。

### 7.1 判断根拠の制限（MUST）

修正前正本の **本文内容** は、生成の判断根拠として使用してはならない。

参照してよいのは、同一性保持に必要な以下の情報に限る。

- doc_id  
- canonical_title  
- document_type  
- 文書全体の構造順序  
- 階層リンク行（先頭および末尾）

### 7.2 new 等価性（MUST）

同一の仕様・テンプレート・生成プロンプトが与えられた場合、  
document_type = `prompt` における recreate の生成結果は、  
new による生成結果と **意味等価** でなければならない。

修正前正本の本文内容が古いこと、  
または現行仕様と乖離していることを理由として、  
生成結果を変化させてはならない。

### 7.3 適用範囲の限定（MUST）

本節の特則は、document_type が `prompt` の場合にのみ適用される。  
他の document_type に適用してはならない。

---

## 8. 不変条件違反時の扱い（FAIL-FAST / MUST）

本規約で定義した不変条件が満たされない場合、  
LLM は **生成フェーズを開始してはならない**。

この判定は、生成フェーズ実行規約における  
**Phase 0（入力検証）** の拘束条件として扱われる。

不変条件違反を、  
推測・補完・再解釈・後続フェーズでの調整によって  
回避してはならない。

---

## 9. 他規約との関係（MUST）

本規約は、以下の規約と組み合わせて適用される。

- 生成フェーズ実行規約
- prompt 成立条件規約
- 判定テーブル再掲要件規約
- ENUM 再掲要件規約

本規約と他規約が矛盾する場合、  
**本規約で定義された不変条件を優先**する。
