# LLM-MANAGEDブロック規約

本書は、HLDocS における **LLM-MANAGED ブロック**（HTML コメント）の役割、配置、必須フィールド、および doc_id の維持ルールを定義する。

---

## 1. 位置付け

- LLM-MANAGED ブロックは **ドキュメント同一性**と **機械可読なメタデータ**を担保するための宣言である。
- 本ブロック内の内容は **LLM のみが編集することを前提**とする。
- 人間による直接編集は、同一性・追跡性を破壊する可能性があるため原則禁止とする。

## 2. 配置（MUST）

- LLM-MANAGED ブロックは **ドキュメント先頭**に配置する。
- 先頭の順序は、共通ドキュメント構造で定義された順序に従う。

## 3. 必須フィールド（MUST）と意味

- `doc_id`
  - 恒久的ドキュメント識別子。
  - 内容・ファイル名・パス・見出し構造と独立であり、**論理同一性の鍵**として用いる。
- `lang`
  - 本文の言語コード（例：ja-JP）。
  - 翻訳版は `lang` のみを変え、`doc_id` は維持する。
- `canonical_title`
  - 正規タイトル。
  - 表示・検索のための名称であり、**同一性の鍵ではない**（変更され得る）。
- `document_type`
  - ドキュメントの役割（spec / index / template 等）。
  - 運用上の都合で変更され得るため、**同一性の鍵ではない**（変更しても doc_id は維持し得る）。
- `canonical_document`
  - 当該ドキュメントが **正規成果物**であるかを示す。
  - Transport Encoding の要否や既定 transport の判断材料として用いる。
- `transport`
  - 提示・回収方法の候補（配列、先頭優先）。
  - Transport Encoding の適用・復元（roundtrip）の前提を明示する。

## 4. doc_id の定義（MUST）

- doc_id は恒久的ドキュメント識別子である
- 以下と完全に独立である  
  ファイル名 / ディレクトリ構成 / 言語 / 番号 / 内容・意味
- 内容更新・移動・改名でも doc_id は変更しない
- 翻訳版は原文と同一 doc_id を使用する

### 4.1 新規生成規則
- 値が空、または __AUTO__ の場合は新規生成を行う
- 形式：doc-YYYYMMDD-HHMMSSZ-XXXX
- タイムゾーン：UTC 固定
- XXXX：4桁 base36
- 衝突時：再生成

### 4.2 doc_id 維持ルール（MUST）

- **論理的に同一のドキュメントである限り、doc_id は必ず維持する。**
- `canonical_title` の変更、本文の全面改稿、見出し構造の変更、ファイル移動・改名、フォルダ再編、番号付与変更は、doc_id 変更理由にならない。
- `document_type` の変更が発生しても、論理的に同一であれば doc_id は維持し得る（例：単体仕様が後に「仕様目次（index）」に役割変更される）。

### 4.3 doc_id を変更してよい条件（MAY）

以下は **論理的に別ドキュメント**とみなすため、新しい doc_id を割り当ててよい。

- 明示的な **分割**：1つの文書を複数文書へ分割し、各文書を独立に管理する。
- 明示的な **統合**：複数文書を1つに統合し、旧文書を廃止する。
- **置換**：内容の継承をせず、別概念として作り直す（過去版の継承を意図しない）。
- **新規作成**：従来存在しなかった概念・役割として新規に起こす。

### 4.4 禁止（MUST NOT）

- 生成や差し替えの都合で、doc_id を再生成してはならない。
- 可読性のために意味語を doc_id に含めてはならない。
