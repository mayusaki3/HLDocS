# 生成プロンプト運用規約

本書は、HLDocS における **ドキュメント生成時の運用モデル**および  
**生成プロンプトとテンプレートの責務分離**を定義する。

---

## 1. 基本前提（MUST）

- 生成時、HLDocS の仕様本文は LLM に与えない。
- LLM は会話履歴の保持を前提としてはならない。
- 生成結果は単体で完結し、再現可能でなければならない。

---

## 2. 合成モデル（MUST）

HLDocS は、以下を **合成した指示集合**を LLM に与える。

- 共通ドキュメントテンプレート
- document_type 別テンプレート（本文部分）
- 共通生成プロンプト
- document_type 別生成プロンプト

> 合成は必須条件ではない。  
> **最終的に LLM が受け取る指示集合全体**が、本規約と関連仕様を満たしていればよい（MUST）。

---

## 3. テンプレートの責務（MUST）

- 構造（骨格）のみを規定する。
- 共通テンプレートは全体構造を定義する。
- document_type 別テンプレートは本文構造のみを定義する。
- **判断ロジックを含めてはならない（MUST NOT）**。

---

## 4. 生成プロンプトの責務（MUST）

- LLM の判断・振る舞い・検査を規定する。
- 共通生成プロンプトは全 document_type 共通の規則を定義する。
- document_type 別生成プロンプトは当該 type 固有の判断規則を定義する。

---

## 5. LLM-MANAGED 値決定要件（MUST）

生成プロンプト（単一または合成）は、以下を満たさなければならない。

- LLM-MANAGED に記載可能なキーの一覧を明示する。
- 各キーの決定方法（新規生成／既存維持／既定値）を明示する。

---

## 6. 禁止事項（MUST NOT）

- 編集履歴・作業指示（例：「追加」「修正」）を本文に含めない。
- 差分・変更理由の記載は外部管理（Git 等）に委ねる。
