# 生成プロンプト運用規約

本書は、HLDocS における **ドキュメント生成時の運用モデルおよび生成プロンプトの責務**を定義する。
HLDocS は、テンプレートおよび生成プロンプトを合成して LLM に与える生成方式を前提とする。

---

## 1. 基本前提（MUST）

- ドキュメント生成時、仕様本文を LLM に与えない。
- LLM は過去の会話文脈が維持されていることを前提としてはならない。
- 生成結果は単体で完結し、再現可能でなければならない。

## 2. テンプレートおよび生成プロンプトの合成モデル（MUST）

HLDocS におけるドキュメント生成は、以下の要素を **合成した指示集合**を LLM に与えることを前提とする。

- 共通ドキュメントテンプレート  
- document_type 別テンプレート（本文部分）  
- 共通生成プロンプト  
- document_type 別生成プロンプト  

生成プロンプトは単一である必要はなく、  
**最終的に LLM が受け取る指示集合全体として、本規約および関連仕様の要件を満たさなければならない（MUST）**。

## 3. テンプレートの責務（MUST）

- テンプレートはドキュメントの構造を規定する。
- 共通テンプレートはドキュメント全体の骨格を定義する。
- document_type 別テンプレートは本文部分のみを対象とする。
- テンプレートは判断ロジックを含んではならない（MUST NOT）。

## 4. 生成プロンプトの責務（MUST）

- 生成プロンプトは LLM の判断および振る舞いを規定する。
- 共通生成プロンプトは、すべての document_type に共通する判断規則を定義する。
- document_type 別生成プロンプトは、当該 document_type 固有の判断規則を定義する。

## 5. LLM-MANAGED ブロック値決定要件（MUST）

生成プロンプト（単一または複数の合成）は、以下を結果として満たさなければならない。

- LLM-MANAGED ブロックに記載可能なキーの一覧を明示する。
- 各キーについて、以下のいずれかの決定方法を明示する。
  - 新規生成
  - 既存値の維持
  - 既定値の適用

## 6. 禁止事項（MUST NOT）

- 編集履歴や作業指示を示す表現を本文に含めてはならない。
  - 例：「追加：」「○○を修正」
- 差分や変更理由の記述は、Git 等の外部管理に委ねる。
