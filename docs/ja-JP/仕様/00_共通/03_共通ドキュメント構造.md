# 共通ドキュメント構造

本書は、HLDocS において作成されるすべてのドキュメントに共通する  
**文書構造・配置規則・必須要素**を定義する。

本書は、  
各 document_type 固有の内容や意味論を定義するものではなく、  
**文書の外枠構造（共通構造）**のみを対象とする。

---

## 1. 基本方針

- HLDocS ドキュメントは Markdown を正規表現形式とする
- すべてのドキュメントは、本書で定義する共通構造に従う
- 共通構造は **再現可能なテンプレート生成**を目的とする
- 本書で規定される空行・区切り線は、表示装飾ではなく **構造要素**である
- ファイル名・ディレクトリ構成・番号は **意味論を持たない**

---

## 2. 文書全体構造（MUST）

HLDocS ドキュメントは、以下の順序と構成を **必ず**持つ。

1. LLM-MANAGED ブロック  
2. 空行  
3. 階層リンク行  
4. 空行  
5. タイトル  
6. 空行  
7. 本文  
8. 空行  
9. 区切り線（`---`）  
10. 空行  
11. フッタ階層リンク  

本章で規定される空行および区切り線は、  
**共通ドキュメント構造の一部として必須**であり、  
省略・追加・移動してはならない。

---

## 3. LLM-MANAGED ブロック

### 3.1 役割

LLM-MANAGED ブロックは、  
ドキュメントの **管理用メタデータ**を定義するためのブロックである。

- 文書内容そのものではない
- 本文とは独立して管理される
- 詳細な規約は [LLM-MANAGED ブロック規約](./04_LLM-MANAGEDブロック規約.md) に従う

本書では、LLM-MANAGED ブロックの内部構造・キー定義は扱わない。

### 3.2 記載位置と形式

- 文書先頭に必ず配置する
- HTML コメント形式で記述する
- 本文からは参照しない

---

## 4. 階層リンク

- 文書の先頭および末尾に配置する
- 階層は `>` 区切りで表現する
- 末尾は必ず当該ドキュメント自身を指す

---

## 5. タイトル

- 文書の主題を簡潔に示す
- `#` 見出しを用いる
- canonical_title と一致していることが望ましい

---

## 6. 本文

- 本文の構造・内容は document_type 別仕様により定義される
- 本書は本文の意味論・詳細構造を規定しない

### 補足（誤解防止・固定化）

- 本書で規定する空行・区切り線は **共通構造（外枠）**に関するものである
- 本文（document_type 別テンプレートが定義する領域）の内容表現は本書の対象外である
- 本文内における空行や区切り線の使用可否・意味は、本文仕様に従う
- 本文内への空行・区切り線の追加を、本書は **禁止しない**

---

## 6.1 spec / template / prompt の位置づけ補足（固定化）

本書で定義する **共通ドキュメント構造**は、  
document_type が `spec` / `template` / `prompt` のいずれであるかに関わらず、  
**すべての HLDocS ドキュメントに共通して適用される外枠構造**である。

- `spec`  
  - 仕様本文は「本文」領域に記載される  
  - 本文の意味論・章構成は、共通構造ではなく spec 別仕様に属する

- `template`  
  - テンプレート本文は「本文」領域に記載される  
  - テンプレートとして解釈される範囲・マーカー規約は、  
    共通ドキュメント構造ではなく生成プロンプト運用規約・template 別仕様に属する

- `prompt`  
  - プロンプト本文は「本文」領域に記載される  
  - 指示内容・禁止事項・生成制約は、  
    共通ドキュメント構造ではなく prompt 別仕様および生成プロンプト運用規約に属する

本書は、  
これら `spec` / `template` / `prompt` の **意味論的差異や役割分担を定義しない**。

それらの定義は、  
それぞれ対応する仕様書（spec / template / prompt 別仕様）および  
生成プロンプト運用規約に委ねられる。

---

## 7. ドキュメント並べ替え番号規定（MUST）

- ファイル名およびフォルダ名は、  
  ファイルシステム上の並び順を制御する目的に限り、  
  自由に先頭へ番号を付与してよい  
  （番号付与以外の名称変更は行ってはならない）
- 番号は **NN_ 形式**とする  
  - N の桁数は自由である  
  - 末尾は必ず `_` で終わる
- これらの番号は、  
  **意味・役割・仕様上の区別を一切持たない**

### 位置づけ補足（固定化）

本規定は、文書構造や本文仕様とは独立した  
**HLDocS ドキュメント運用上の前提規約**である。

- 並び順制御のための現実的要請と、
- 仕様上の意味論・依存関係

を明確に分離することを目的とし、  
将来にわたって **共通ドキュメント構造に含めるものとする**。

---

## 8. フッタ階層リンク

- 文書末尾に配置する
- 先頭の階層リンクと同一内容とする
