# 表示名リンク成立条件補足

本書は、表示名リンク規約と prompt 成立条件規約との関係を補足する。

本書は、表示名リンク規約違反を、
単なる表示上の推奨事項ではなく、
HLDocS の生成成立条件に関わる要件として定義する。

本書は、「HLDocS 前提条件」という仕様が参照可能である場合にのみ適用される。
- 「HLDocS 前提条件」が入力として与えられていない場合、
または当該仕様に基づく適用可否が確定していない場合、
本書に基づく判断・生成・再作成・工程実行を行ってはならない。
- この場合、許可されるのは、
提示された文書の受理および存在確認、
ならびに前提条件が未参照または未確定である旨の通知のみとする。
- 「HLDocS 前提条件」が入力文書一覧に含まれない場合、生成・再作成・成果物提示を一切行ってはならない。

---

## 1. 基本方針

生成プロンプトは、表示名リンク規約に従った出力を生成しなければならない（MUST）。

表示名リンク規約に違反する出力を許容する生成プロンプトは、
prompt 成立条件規約における成立条件を満たしていないものとして扱う（MUST）。

---

## 2. 表示名リンク規約との整合性（MUST）

生成プロンプトは、
人間向け表示において、
以下を直接表示してはならない（MUST NOT）。

- 物理ファイル名
- 物理ディレクトリ名
- 並び順制御番号
- 物理パス

他ドキュメントを参照する場合は、
番号なし表示名と Markdown Link を組み合わせた形式を使用しなければならない（MUST）。

---

## 3. 許可される形式

以下は許可される。

```markdown
[前提条件](./仕様/00_共通/01_前提条件.md)
```

```markdown
[表示名リンク規約](./仕様/00_共通/12_表示名リンク規約.md)
```

---

## 4. 禁止される形式

以下は禁止する（MUST NOT）。

```markdown
[01_前提条件](./仕様/00_共通/01_前提条件.md)
```

```text
01_前提条件.md を参照する。
```

```text
docs/ja-JP/仕様/00_共通/01_前提条件.md
```

---

## 5. 成立条件との関係

生成プロンプトが以下を許容する場合、
当該生成プロンプトは成立していないものとして扱う（MUST）。

- 番号付きファイル名の表示
- 物理パスの文中表示
- 並び順制御番号の表示名利用
- 番号なし表示名への変換漏れ

これは、表示名リンク規約違反が、
単なる UI 上の問題ではなく、
HLDocS の canonical / human-facing separation に違反するためである。

---

## 6. HTML 可視化との関係

本補足規約は、Markdown → HTML visualization の成立条件にも影響する。

Markdown 上で番号付き物理名を表示している場合、
HTML 側でも管理情報が利用者向け表示へ漏出する。

そのため、表示名リンク規約を満たさない生成結果は、
HTML 可視化前提の HLDocS ドキュメントとして不成立とみなす（MUST）。
