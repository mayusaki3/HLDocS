# HTML生成PoC実装設計

## 1. 位置付け

本書は、HLDocS 自身を対象とした HTML 生成 PoC-1 の実装設計メモである。

本書は正規仕様ではなく、PoC 実装・検証に向けた作業入力として扱う。

---

## 2. PoC-1 の目的

PoC-1 では、HLDocS 自身の Markdown 正本文書群から、最小限の HTML ドキュメントを生成できることを確認する。

主な確認対象は以下とする。

- overview profile
- reference profile
- HTML Site Manifest
- Manifest ベースの内部リンク
- Markdown 正本へのリンク
- stale 状態の基本表示
- `docs/ja-JP/HTMLドキュメント` への出力

---

## 3. 非対象

PoC-1 では以下を対象外とする。

- test-report profile の完全生成
- 実テスト結果の取り込み
- evidence 表示
- coverage dashboard
- spec → testspec → code → testcode → test result の完全可視化
- GitHub Pages 公開
- 公開先アダプタ
- 完全な Web アプリケーション化

対象外ページは、必要に応じて `not generated` と表示する。

---

## 4. 入力

PoC-1 の入力は、HLDocS の Markdown 正本文書とする。

主な入力候補：

```text
docs/ja-JP/仕様/00_共通/*.md
docs/ja-JP/仕様/10_document_type/**/*.md
docs/ja-JP/テンプレート/**/*.md
docs/ja-JP/使い方/*.md
docs/ja-JP/目次.md
```

初期実装では、まず以下を対象としてよい。

```text
docs/ja-JP/仕様/00_共通/*.md
docs/ja-JP/目次.md
```

---

## 5. 出力

PoC-1 の出力先は以下とする。

```text
docs/ja-JP/HTMLドキュメント
```

初期出力構成：

```text
HTMLドキュメント/
├── overview/
│   └── index.html
├── reference/
│   └── *.html
├── manifest/
│   └── site-manifest.json
└── index.html
```

PoC-1 では、以下は未生成でもよい。

```text
HTMLドキュメント/traceability/
HTMLドキュメント/reports/
HTMLドキュメント/assets/
```

---

## 6. 最小 generator の役割

最小 HTML generator は、以下を行う。

1. Markdown 正本文書を列挙する
2. LLM-MANAGED ブロックから metadata を抽出する
3. Markdown 見出しから章構造を抽出する
4. reference HTML を生成する
5. overview HTML を生成する
6. index HTML を生成する
7. HTML Site Manifest を生成する
8. Manifest に存在するページだけを内部リンク対象にする

---

## 7. metadata 抽出

各 Markdown 文書から、少なくとも以下を抽出する。

- `doc_id`
- `lang`
- `canonical_title`
- `document_type`
- `canonical_document`
- source markdown path
- source hash
- heading list

`sec_id` は、PoC-1 では存在する場合のみ抽出する。

存在しない場合、推測生成してはならない。

---

## 8. reference HTML

reference HTML は、Markdown 1文書に対応する Document Page とする。

最低限表示する項目：

- canonical_title
- document_type
- doc_id
- source markdown link
- heading list
- Markdown 本文の HTML 表示

リンク表示名には、物理ファイル名・物理パス・並び順制御番号を表示しない。

---

## 9. overview HTML

overview HTML は、HLDocS 全体像を把握するためのページとする。

最低限表示する項目：

- HLDocS の目的
- 共通仕様一覧
- document_type 一覧
- HTML生成PoCの範囲
- generated / canonical の関係
- `not generated` の対象

---

## 10. index HTML

`HTMLドキュメント/index.html` は、HTML ドキュメント全体の入口とする。

最低限表示する項目：

- overview へのリンク
- reference 一覧へのリンク
- Manifest 生成日時
- stale 状態概要
- not generated 表示

---

## 11. HTML Site Manifest

PoC-1 では、`site-manifest.json` を生成する。

最低限の項目：

```json
{
  "generated_at": "ISO-8601",
  "profile": ["overview", "reference"],
  "pages": [
    {
      "page_id": "...",
      "profile": ["reference"],
      "source_markdown": "...",
      "canonical_title": "...",
      "doc_id": "...",
      "sec_id": [],
      "output_html_path": "...",
      "source_hash": "...",
      "stale": false,
      "link_targets": []
    }
  ]
}
```

---

## 12. stale 判定

PoC-1 では、stale 判定は以下の最小方式とする。

- HTML 生成時に source hash を Manifest へ記録する
- 再生成時に source hash が変化していれば stale 候補とする
- 初回生成時は `stale: false` とする

完全な stale 判定アルゴリズムは後続仕様化対象とする。

---

## 13. 実装候補

PoC-1 の generator は、まず Python スクリプトとして実装する方針がよい。

想定配置：

```text
tools/html_generator/
├── generate_html.py
├── markdown_loader.py
├── metadata_parser.py
├── html_writer.py
└── manifest_writer.py
```

ただし、初期 PoC では単一ファイル実装から開始してよい。

---

## 14. 実行例

想定コマンド：

```bash
python tools/html_generator/generate_html.py \
  --input docs/ja-JP \
  --output docs/ja-JP/HTMLドキュメント \
  --profile overview,reference
```

---

## 15. 確認項目

PoC-1 実装後、以下を確認する。

- `HTMLドキュメント/index.html` が生成される
- `overview/index.html` が生成される
- `reference/*.html` が生成される
- `manifest/site-manifest.json` が生成される
- Manifest に存在しないページへのリンクが生成されない
- Markdown 正本リンクが存在する
- リンク表示名に物理ファイル名や番号が露出しない
- `not generated` 表示ができる
