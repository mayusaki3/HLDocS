# HTML生成PoC検証結果運用方針

## 1. 位置付け

本書は、HLDocS における HTML 生成 PoC の検証結果を、どのように記録し、後続仕様へ反映するかを整理するための方針である。

本書は正規仕様ではなく、PoC 実施中のフィードバック運用記録として扱う。

---

## 2. 基本方針

HTML 生成 PoC の検証結果は、PoC 実施中に直接仕様へ逐次反映しない。

PoC 中に得られた実データ・問題・改善案・未決事項は、まず `docs/ja-JP/フィードバック` 配下へ集約する。

PoC 完了後、蓄積されたフィードバックを整理し、必要な内容を HTML 系仕様へ一括反映する。

---

## 3. 理由

HTML 生成仕様は、以下の実データに強く依存する。

- 実際の HTML 出力形式
- HTML Site Manifest の実フォーマット
- page_id 命名規則
- HTML ファイル名生成規則
- Markdown 正本リンク形式
- not generated 表示形式
- stale 判定方式
- overview / reference の実表示内容
- generator 実行インターフェース

これらは PoC 実施前に確定しすぎると、実装結果と仕様が乖離する可能性がある。

そのため、PoC 中は概念仕様を維持し、実装・検証で得た知見をフィードバックへ蓄積する。

---

## 4. フィードバックへ記録する対象

PoC 実施中は、少なくとも以下をフィードバックとして記録する。

### 4.1 Manifest 関連

- `site-manifest.json` の実フォーマット
- 必須項目・任意項目
- page_id 命名
- source_hash 算出方法
- link_targets の実表現
- stale 状態の表現

---

### 4.2 HTML 出力関連

- `index.html` の構成
- `overview/index.html` の構成
- `reference/*.html` の構成
- Markdown 正本リンク形式
- not generated 表示
- HTML 内部リンク形式

---

### 4.3 ディレクトリ構成関連

- 実生成ディレクトリ
- 未生成ディレクトリの扱い
- assets の有無
- manifest 配置
- ファイル名生成規則

---

### 4.4 stale 判定関連

- 初回生成時の扱い
- source_hash 差分検出
- generated_at の扱い
- stale 表示位置
- stale 判定の限界

---

### 4.5 生成ツール関連

- generator 配置
- 実行コマンド
- 引数仕様
- profile 指定
- 再生成方法
- エラー時の扱い

---

### 4.6 仕様反映候補

- 概念仕様へ昇格すべき内容
- 実装依存として残す内容
- 後続 PoC へ回す内容
- 別プロジェクト検証が必要な内容

---

## 5. 仕様へ一括反映するタイミング

以下を満たした時点で、フィードバックを整理し、HTML 系仕様へ一括反映する。

1. HLDocS 自身を対象に overview / reference が生成できている
2. `site-manifest.json` が生成できている
3. Manifest ベースで内部リンクを制御できている
4. Markdown 正本リンクが生成できている
5. not generated 表示が確認できている
6. stale 状態の基本表示が確認できている
7. PoC の制約と未検証範囲が明確になっている

---

## 6. 一括反映先

PoC 完了後、主に以下へ反映する。

- HTMLドキュメント生成規約
- HTML Site Manifest規約
- HTML出力単位規約
- HTMLディレクトリ構成規約

必要に応じて、以下にも反映する。

- HTML Traceability可視化規約
- HTML検査成績表規約
- 共通ドキュメント構造
- 表示名リンク規約
- 共通仕様完全一覧入力規約

---

## 7. 反映しない内容

以下は、PoC 完了時点で即仕様化しなくてもよい。

- test-report profile の詳細
- 実テスト結果の入力形式
- evidence 詳細形式
- coverage dashboard 詳細
- GitHub Pages 公開手順
- 公開ツール・公開先アダプタ詳細

これらは、実装・テストを持つ別プロジェクトでの PoC 後に仕様反映を検討する。

---

## 8. 現時点の方針

現時点では、HTML 系仕様 15〜20 は概念仕様として維持する。

PoC 実施中の検証結果はフィードバックへ集約し、PoC 完了後にまとめて仕様へ反映する。
