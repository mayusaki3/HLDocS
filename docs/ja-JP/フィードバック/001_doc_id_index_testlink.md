# フィードバック #001  
doc_id・index役割・テスト仕様リンクに関する整理（追補反映版）

## 1. 背景

本フィードバックは、AIChaBo ドキュメント再構成の検証過程で発生した  
HLDocS 仕様解釈の揺れ・誤生成リスクを整理し、  
**LLM が推測や自動補完を行わないための拘束条件を明文化する**ことを目的とする。

本書は仕様変更ではなく、  
**検証・運用フェーズ向けの判断指針の記録**である。

---

## 2. 決定事項と補足整理

### 2.1 doc_id とテスト番号の独立（決定）

- doc_id は HLDocS 管理下の **恒久的ドキュメント識別子**
- テスト番号体系は **HLDocS 管轄外**
- 両者を混同してはならない

#### doc_id の性質
- リポジトリ内で一意
- 翻訳版を含めて同一 doc_id を使用
- ファイル移動・改名があっても不変
- 言語コード・パス・ファイル名を含めない

#### 補足（記録のみ）
- 仕様テスト／網羅テスト等の分類は実運用上重要
- ただし、これは **将来のテスト仕様テンプレート側で扱う**
- HLDocS 本体仕様には含めない

---

### 2.2 index.md の Canonical 扱い（役割ベース）

- HLDocS は **index.md というファイル名を前提としない**
- 規定するのは「役割」

#### Canonical 扱いとなる条件
- doc_id を持つ
- 階層リンク行を持つ
- 配下ドキュメントへのリンクを列挙する

#### 推奨表現
- 「index.md」ではなく  
  **「ディレクトリ直下のナビゲーション用ルートドキュメント」**

---

### 2.3 ドキュメント番号（90番台等）の扱い

- 番号に意味は持たせない
- 並び順調整のための人間向け番号
- HLDocS として予約番号は設けない
- 連番への変更も問題なし

---

### 2.4 テスト仕様とのリンク粒度（AIChaBo 方針）

- テスト仕様ドキュメントは **Canonical 扱い**
- doc_id を付与する
- 仕様 ↔ テストのリンク粒度は **ファイル単位**
- 粒度拡張は type:testcase 策定後に再検討

---

## 3. 検証用プロンプトへの反映事項

以下は、検証用プロンプトに明示的に追加する制約である：

- doc_id とテスト番号を混同しない
- index.md を前提とした生成を行わない
- 番号（90等）に意味を見出さない
- テスト仕様は Canonical 扱い（AIChaBo）
- 目次.md はナビゲーション専用とみなす

---

## 4. 本フィードバックの位置づけ

- HLDocS 初版仕様の変更ではない
- LLM の誤推測・過剰設計を防ぐための拘束条件
- 検証フェーズ専用の判断材料
