# HTML要約構成レイヤー方針

## 1. 位置付け

本書は、HLDocS の HTML ドキュメント生成における「要約構成レイヤー」の導入方針を記録する。

本書は正規仕様ではなく、HTML生成PoCで得られた構造上の課題と改善方針を整理するフィードバック文書として扱う。

---

## 2. 背景

現在の HTML 生成 PoC は、Markdown 正本文書を機械的に HTML へ変換する最小実装である。

この方式は reference 表示には有効であるが、当初想定していた以下の目的には不足がある。

- 全体像の把握
- 仕様構造の可視化
- 概念関係の理解
- 入門用説明
- 全体像から詳細へ進む navigation
- 仕様群の読み順・依存関係の提示

そのため、HTML 生成を単純な Markdown viewer に留めず、構造化された overview / visualization を生成できる仕組みへ拡張する必要がある。

---

## 3. 基本方針

HTML 生成は、以下の三層構造として整理する。

```text
Markdown 正本
↓
要約構成レイヤー
↓
HTML 生成 tool
↓
HTML ドキュメント
```

Markdown 正本は canonical specification とする。

要約構成レイヤーは、HTML ドキュメント生成のための中間生成物であり、Markdown 正本を置き換えない。

HTML 生成 tool は、要約構成レイヤーを入力として、機械的に HTML を生成する。

---

## 4. 要約構成レイヤーの役割

要約構成レイヤーは、Markdown 正本群から HTML ドキュメント向けの構成情報を整理した中間表現とする。

主な役割：

- 全体像の要約
- 仕様群の構造化
- document_type ごとの整理
- 仕様間関係の整理
- 読み順・導線の定義
- overview / reference / traceability / test-report の生成材料化
- not generated 対象の明示
- HTML navigation の設計

---

## 5. LLM と tool の責務分離

HTML 生成 tool は、原則として機械的変換を担当する。

LLM は、必要に応じて以下を担当する。

- Markdown 正本群から要約構成レイヤーを作成する
- 全体像を整理する
- 読み順・導線を提案する
- 概念関係を抽出する
- 入門説明用の要約を作成する

つまり、LLM は HTML を直接生成するのではなく、HTML 生成 tool が扱いやすい中間構成情報を生成する役割を持つ。

---

## 6. 要約構成レイヤーが存在しない場合

要約構成レイヤーが存在しない場合、HTML 生成 tool は Markdown 正本から最小限の構成情報を自動抽出して HTML を生成してよい。

これは現在の PoC 実装と一致する。

この場合、生成される HTML は主に以下となる。

- reference HTML
- 最小 overview
- index
- Manifest

ただし、高度な全体構造可視化や概念図は限定的となる。

---

## 7. 要約構成レイヤーが存在する場合

要約構成レイヤーが存在する場合、HTML 生成 tool はそれを優先入力として扱う。

この場合、以下をより高品質に生成できる。

- 全体像ページ
- 入門ページ
- navigation tree
- document_type map
- dependency graph
- lifecycle map
- traceability map
- generated / not generated matrix
- stale dashboard

---

## 8. 配置方針

要約構成レイヤーは、HTML ドキュメント生成結果と同じ領域配下に配置する方針とする。

配置候補：

```text
docs/ja-JP/HTMLドキュメント/summary-structure/
```

または：

```text
docs/ja-JP/HTMLドキュメント/structure/
```

現時点の仮称は「要約構成レイヤー」とするが、後続で正式名称を決定する。

---

## 9. 想定ファイル

要約構成レイヤーでは、少なくとも以下のファイルを検討する。

```text
summary-structure/
├── site-summary.json
├── navigation.json
├── overview.json
├── document-map.json
├── profile-map.json
└── not-generated.json
```

必要に応じて、Markdown または YAML 形式を併用してもよい。

---

## 10. 全体像から詳細への導線

HTML ドキュメントは、以下の導線を重視する。

```text
全体像
↓
カテゴリ
↓
文書群
↓
章・節
↓
Markdown 正本
```

reference HTML は詳細閲覧用とし、overview / map / dashboard は全体把握用とする。

---

## 11. 現行PoCとの差分

現行 PoC は以下に相当する。

```text
Markdown 正本
↓
最小構成情報を tool が抽出
↓
HTML tool変換
```

今後は、以下へ拡張する。

```text
Markdown 正本
↓
LLM または tool による要約構成レイヤー生成
↓
HTML tool変換
```

---

## 12. 仕様反映候補

PoC 後、以下の仕様へ反映を検討する。

- HTMLドキュメント生成規約
- HTML Site Manifest規約
- HTML出力単位規約
- HTMLディレクトリ構成規約
- HTML Traceability可視化規約

特に、要約構成レイヤーの位置付け、配置、優先順位、生成責務を仕様化する必要がある。

---

## 13. 未決事項

以下は未決事項とする。

- 正式名称
- JSON / YAML / Markdown のどれを正とするか
- LLM生成物として扱うか、tool生成物として扱うか
- stale 判定対象に含めるか
- Manifest との関係
- HTML生成結果と同じ generated artifact とみなすか
- 手動編集可能な operational input とするか
