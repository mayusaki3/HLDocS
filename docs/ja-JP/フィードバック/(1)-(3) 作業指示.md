# document_type:index 仕様

## 1. 目的
- 文書体系の“ナビゲーション”責務を document_type で定義する。
- ファイル名（index.md/README.md/目次.md 等）に依存せず、役割ベースで入口文書を扱えるようにする。

## 2. 定義
- document_type: index の文書を「ナビゲーション文書」と定義する。:contentReference[oaicite:32]{index=32}
- ナビゲーション文書は、配下ドキュメントへのリンク列挙を主目的とする。:contentReference[oaicite:33]{index=33}

## 3. 責務（MUST）
- 配下（スコープ内）のドキュメントをカテゴリ別に列挙し、到達可能にする。
- リンク列挙は「相対パス」を基本とする（リポジトリ内移動耐性のため）。
- 自身が“最上位”である場合、階層リンク行は自身タイトルのみとする（最上位ノード規約に整合）。:contentReference[oaicite:34]{index=34}

## 4. 非責務（MUST NOT）
- 文書種別をファイル名で決めない（index.md 前提にしない）。
- 番号（NN_）の意味付けを行わない（並び順調整のみ）。:contentReference[oaicite:36]{index=36}
- doc_id とナビゲーション構造（フォルダ/ファイル名/言語）を結び付けない。:contentReference[oaicite:37]{index=37}

## 5. 推奨構造（SHOULD）
- 章立て例：
  - 目的
  - 仕様（リンク一覧）
  - テンプレート（リンク一覧）
  - 使い方（リンク一覧）
  - （必要に応じて）ガイド、運用、補足
- 各セクション配下は箇条書きで列挙する（差分管理しやすいため）。

## 6. output_mode / transport
- index 文書も共通規約に従う（output_mode は ui-copy を推奨、ただし保存成果物は canonical-md）。

# document_type:index 生成プロンプト（LLM向け）

あなたは HLDocS 準拠ドキュメントを管理する LLM である。:contentReference[oaicite:40]{index=40}  
次の条件で document_type:index を生成または更新せよ。

## 入力
- 共通ドキュメントテンプレート
- document_type:index テンプレート（本文骨子）
- 配下に存在するドキュメント一覧（パスと表示名）
- output_mode 指定（未指定なら ui-copy）

## MUST
- 正規構造（LLM-MANAGEDブロック／階層リンク行／区切り線）を維持する。:contentReference[oaicite:42]{index=42}
- doc_id は既存更新時に変更しない。新規時は「doc-YYYYMMDD-HHMMSSZ-XXXX」で生成する（UTC固定、衝突時再生成）。
- ファイル名で役割を決めない（index.md 前提にしない）。
- 配下文書へのリンクをセクション別に列挙し、到達可能性を保証する。:contentReference[oaicite:45]{index=45}

## MUST NOT
- doc_id に意味語を含めない。:contentReference[oaicite:46]{index=46}
- 番号（NN_）へ意味を付与しない。:contentReference[oaicite:47]{index=47}
- タイトルをファイル名都合で劣化させない。:contentReference[oaicite:48]{index=48}

## output_mode: ui-copy の場合
- 出力全体を1つのコピー単位として扱えるようにする。
- 本文中にバッククォート3つが必要になった場合のみ `<HL-FENCE>` に置換する（ただし index 文書では通常不要）。
