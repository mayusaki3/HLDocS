# (A) 共通チェック項目（案：15項目、NG/WARN）

## A-1. NG（エラー：必ず失敗扱い）
NG-01: LLM-MANAGED ブロックがドキュメント先頭に存在しない  
NG-02: LLM-MANAGED ブロックが HTML コメント形式でない（<!-- ... --> でない）  
NG-03: LLM-MANAGED 必須キー欠落（doc_id / lang / canonical_title / document_type / canonical_document / transport）  
NG-04: LLM-MANAGED ブロック直後に「空行 → 階層リンク行 → 空行」が成立していない（共通ドキュメント構造違反）  
NG-05: 末尾が「空行 → --- → 空行 → 階層リンク行（再掲）」になっていない  
NG-06: 階層リンク行（先頭）と（末尾再掲）が一致しない  
NG-07: transport が配列でない（例: transport: true_out は NG）  
NG-08: transport の要素に許可値以外が含まれる（true_out / ui_copy / download 以外）  
NG-09: doc_id 形式が規約違反（doc-YYYYMMDD-HHMMSSZ-XXXX / UTC固定 / XXXX=4桁base36）  
NG-10: canonical_document が true/false 以外、または欠落  
NG-11: document_type が空、または未定義（運用側で許可ENUMに照合）  
NG-12: 本文に編集指示・作業指示が混入（例: 「追加:」「差し替え:」「修正:」「ここに追記」等）  
NG-13: 本文に「構造の説明」「生成手順の説明」が混入（例: 「以下の構造で出力する」等）  
NG-14: 同一文書内で LLM-MANAGED ブロックが複数存在  
NG-15: 階層リンク行が欠落、または “>” 区切りでない

## A-2. WARN（警告：失敗ではないが要注意）
W-01: canonical_title が空/極端に短い（検索性低下）  
W-02: transport の先頭が ui_copy の場合に、本文に UI を壊しやすい表現（例: コードフェンスや極端な入れ子）が多い  
W-03: canonical_document=true なのに transport が [ui_copy] のみ（回収・正規性運用と衝突しやすい）  
W-04: 階層リンク行が「目次」への導線を含まない（運用の一貫性低下）  
W-05: lang が想定外（例: ja-JP以外） ※多言語運用時は許可リストで制御

# (B) document_type 別チェックの差し込み口（設計）

## B-1. 共通生成プロンプト（改定方針）
- 共通生成プロンプトは、以下の3ブロックを必ず含む
  1) 命令（構造・禁止事項・前提内面化）
  2) 判断規則（LLM-MANAGED 値決定）
  3) 自己検査（共通チェック + typeチェック）
- “検査結果は出力しない”。NGがあれば内部で修正して最終出力のみ。

## B-2. 差し込み口（type-check hook）
- 共通生成プロンプト内に、document_type 固有検査を差し込む「明示領域」を設ける（本文には出さない）

例（概念）:
- [INTERNAL:TYPE_RULES]  ← document_type別プロンプトの判断規則をここに差し込む
- [INTERNAL:TYPE_CHECKS] ← document_type別の自己検査項目をここに差し込む

※ これは「プロンプト合成時の論理区分」であり、成果物本文には一切出力しない。

## B-3. 運用ルール（合成）
- 共通プロンプトは常に適用
- document_type 別プロンプトは該当type時のみ適用
- 共通チェック（A）は全typeで常に実施
- typeチェックは該当typeのみ追加実施

# (C) 外部検証ツール（検討：仕様案）

## C-1. 目的
- LLM自己検査の補助ではなく、最終的な品質ゲートとして
  - 構造破壊
  - 必須メタデータ欠落
  - doc_id/transport 不正
を機械的に検出する。

## C-2. 入力
- 対象ルート: docs/ 配下（既定）
- 対象ファイル: *.md（既定）
- 除外: docs と同階層の世代/versionファイル等（HLDocS管理外）

## C-3. 出力
- 標準出力: 人間可読ログ（NG/WARNの一覧、ファイルパス、行番号または範囲）
- 追加（任意）: JSONレポート出力（--json out.json）
  - files: [{path, ng:[], warn:[]}]
  - summary: {ng_count, warn_count, files_ng, files_warn}

## C-4. 終了コード
- 0: NGなし（WARNはあってもよい）
- 1: NGあり
- 2: ツール実行エラー（I/Oや設定不正）

## C-5. ルールセット
- 共通ルール（A-1/A-2）を実装
- 許可ENUM（document_type等）は設定ファイル化（例: tools/hldocs_rules.json）
  - allow_document_type: ["spec","index","template","prompt"] など
  - allow_transport: ["true_out","ui_copy","download"]
  - forbid_phrases: ["追加:", "差し替え:", ...]（最初は最低限）
- WARN/NGの閾値・運用は設定で調整可能にする

## C-6. CI/ローカル運用案
- ローカル: pre-commit / 手動実行（scripts/validate_hldocs.*）
- CI: PR時に必ず実行（NGでfail）
