# HTML生成要件フィードバック

## 1. 位置付け

本書は、HLDocS における HTML 生成仕様を検討するためのフィードバック記録である。

本書は正規仕様ではなく、後続の HTML visualization / HTML generation 仕様化に向けた検討入力として扱う。

---

## 2. 背景

HLDocS では Markdown を正本としつつ、人間が内容を把握しやすくするための HTML 生成を検討する。

HTML は Markdown 正本を置き換えるものではなく、Markdown 正本から生成される閲覧用・説明用・検査用の Operational Representation として扱う想定である。

---

## 3. 想定用途

### 3.1 全体像把握

仕様の全体像や構成図、概念図など、概要レベルで人間が把握できる情報を生成できること。

想定例：

- 仕様全体の構成図
- 仕様間の関係図
- document_type 関係図
- 生成フロー概念図
- Traceability 概要図
- canonical / operational representation の関係図

---

### 3.2 入門用説明資料

初学者・利用者向けに、HLDocS の考え方や利用方法を説明する HTML 資料を生成できること。

想定例：

- HLDocS の概要
- まず読むべき内容
- ChatGPT UI での基本利用手順
- 仕様本文を直接使う場合
- prompt / template を使う場合
- Preview Release の制約

---

### 3.3 API仕様・テスト仕様・使用方法の整理

API仕様やテスト仕様、使用方法を、人間が見やすく整理された形で表示できること。

想定例：

- API一覧
- エンドポイント別仕様
- テストケース一覧
- テスト番号別表示
- 入力・期待結果・判定条件
- 関連仕様へのリンク

---

### 3.4 検査成績表

テスト結果を検査成績表として見やすく整理できること。

想定例：

- テスト番号
- テスト名
- 対象仕様
- 実行結果
- PASS / FAIL
- 失敗理由
- 証跡
- 関連する spec / testspec / code へのリンク

---

## 4. Markdown 正本へのリンク要件

各 HTML ページから、必要に応じて Markdown 正本の情報へ遷移できること。

最低限、以下のリンクを持つことが望ましい。

- 元 Markdown ファイルへのリンク
- 可能であれば該当 sec_id へのリンク
- 関連仕様へのリンク
- 関連テスト仕様へのリンク
- 関連コード・テストコードへのリンク

---

## 5. HTML 生成結果の配置候補

HLDocS リポジトリ内で HTML 生成結果を管理する場合、配置候補は以下とする。

```text
docs/ja-JP/HTMLドキュメント
```

この配置は、日本語ドキュメント配下に HTML 生成物を置く方針として自然である。

ただし、HTML は Markdown 正本ではなく generated output であるため、以下を明確化する必要がある。

- Markdown 正本とは別管理であること
- HTML 側を編集正本として扱わないこと
- HTML から Markdown へ逆生成しないこと
- HTML 生成物の更新元が Markdown 正本であること
- 生成済み HTML が古くなった場合は stale representation として扱うこと

---

## 6. 配置候補に対する評価

`docs/ja-JP/HTMLドキュメント` は、利用者向けに分かりやすい配置名であり、初期検証には適している。

一方で、将来的に以下を分ける可能性がある。

- HTML 生成仕様
- HTML 生成テンプレート
- HTML 生成結果
- GitHub Pages 等で公開する静的サイト成果物

そのため、初期段階では `docs/ja-JP/HTMLドキュメント` を採用してよいが、正式仕様化時には、生成結果ディレクトリであることを明示する規約を追加する必要がある。

---

## 7. 後続仕様化で検討する項目

後続の HTML visualization / HTML generation 仕様では、少なくとも以下を定義する必要がある。

- Markdown canonical / HTML generated の不変条件
- HTML 出力単位
- HTML 出力先ディレクトリ構成
- doc_id / sec_id の HTML 埋め込み方法
- Markdown 正本へのリンク形式
- 表示名リンク規約との関係
- Traceability 表示形式
- 検査成績表フォーマット
- 静的 HTML と軽量 JavaScript 付き HTML の扱い
- GitHub Pages 等による公開の扱い
- stale representation 判定
- Operational Representation との関係

---

## 8. 現時点の仮方針

現時点では、HTML 生成結果は以下の位置付けとする。

- Markdown 正本から生成される read-only Operational Representation
- 人間向け閲覧・説明・検査用の派生成果物
- 編集正本ではない
- Markdown 正本へのリンクを持つ
- 生成元 Markdown の更新に追従できない場合は stale とみなす
