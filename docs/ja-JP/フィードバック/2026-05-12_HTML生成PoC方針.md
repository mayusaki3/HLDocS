# HTML生成PoC方針

## 1. 位置付け

本書は、HLDocS における HTML ドキュメント生成 PoC の方針を記録する。

本書は正規仕様ではなく、後続の HTML 生成 PoC 実装・検証に向けた検討入力として扱う。

---

## 2. 基本方針

HTML 生成 PoC は、まず HLDocS 自身を対象として実施する。

HLDocS 自身は Markdown 正本仕様群を持つため、以下の検証に適している。

- overview profile
- reference profile
- HTML Site Manifest
- HTML ディレクトリ構成
- Markdown 正本リンク
- doc_id / sec_id 表示
- stale 表示の基本形

一方で、HLDocS 自身は実装コード・テストコード・テスト結果を主対象とするプロジェクトではないため、検査成績表や実テスト結果の検証には適さない。

---

## 3. PoC-1: HLDocS 自身

### 3.1 目的

HLDocS 自身を HTML 化し、HTML 生成基盤を検証する。

### 3.2 対象 profile

PoC-1 では、以下を対象とする。

- overview
- reference

必要に応じて、traceability は概要レベルのみ扱う。

### 3.3 対象外

PoC-1 では、以下は対象外とする。

- test-report
- 実テスト結果
- evidence
- spec → testspec → code → testcode の完全検証
- coverage dashboard

対象外のページ種別は、必要に応じて `not generated` と表示する。

---

## 4. PoC-1 で確認すること

PoC-1 では、少なくとも以下を確認する。

### 4.1 overview 生成

HLDocS の全体像を、人間が把握しやすい HTML として生成できること。

想定内容：

- HLDocS の目的
- 共通仕様一覧
- document_type 一覧
- 生成フェーズ概要
- Canonical Specification / Operational Representation 関係
- HTML 生成仕様群の位置付け

---

### 4.2 reference 生成

Markdown 正本文書を HTML Document Page として生成できること。

想定内容：

- 文書単位 HTML
- canonical_title 表示
- doc_id 表示
- Markdown 正本リンク
- 関連仕様リンク

---

### 4.3 HTML Site Manifest

HTML Site Manifest を生成し、HTML ドキュメント間リンクを Manifest ベースで解決できること。

想定確認：

- generated page list
- source markdown
- doc_id
- output_html_path
- profile
- stale state
- link_targets

---

### 4.4 HTMLディレクトリ構成

生成結果を以下の構成に配置できること。

```text
docs/ja-JP/HTMLドキュメント/
├── overview/
├── reference/
├── traceability/
├── reports/
├── assets/
├── manifest/
└── index.html
```

PoC-1 では、未使用ディレクトリは空または未生成でもよい。

---

### 4.5 Markdown 正本リンク

各 HTML ページから、対応する Markdown 正本へ遷移できること。

リンク表示名には、物理ファイル名・物理パス・並び順制御番号を表示しない。

---

### 4.6 stale 表示の基本形

PoC-1 では、stale 判定の完全自動化までは必須としない。

ただし、HTML / Manifest 上に stale 状態を保持・表示できる構造を確認する。

---

## 5. PoC-2: 別プロジェクト

### 5.1 目的

実装・テスト・テスト結果を持つ別プロジェクトで、Traceability と検査成績表を検証する。

### 5.2 対象候補

PoC-2 では、以下を持つプロジェクトを対象とする。

- spec
- testspec
- code
- testcode
- test result
- evidence

### 5.3 検証対象

PoC-2 では、以下を検証する。

- traceability profile
- test-report profile
- 検査成績表
- evidence 表示
- coverage 表示
- stale result
- spec → testspec → code → testcode → test result

---

## 6. PoC の段階分け

HTML 生成 PoC は、以下の段階で進める。

### Step 1: 静的 HTML 生成

Markdown 正本から、最低限の HTML を生成する。

### Step 2: Manifest 生成

HTML Site Manifest を生成する。

### Step 3: Manifest ベースリンク

HTML ドキュメント間リンクを Manifest に基づいて生成する。

### Step 4: overview / reference の整備

HLDocS 自身の overview / reference を整備する。

### Step 5: stale 表示の基本対応

source_hash または generated_at に基づく stale 表示を試作する。

### Step 6: 別プロジェクトで test-report 検証

実テスト結果を持つ別プロジェクトで、検査成績表・Traceability を検証する。

---

## 7. 現時点の仮方針

PoC-1 では、HLDocS 自身を対象に以下を生成する。

- `overview/index.html`
- `reference/*.html`
- `manifest/site-manifest.json`
- `index.html`

PoC-1 では、`reports/` および完全な `traceability/` は未生成または `not generated` として扱う。
