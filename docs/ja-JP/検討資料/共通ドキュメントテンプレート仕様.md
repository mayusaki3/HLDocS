# HLDocS 共通ドキュメントテンプレート仕様（初版・検討・改訂）

本書は、HLDocS における
共通ドキュメントテンプレートの構造・命名・翻訳規約を定義する。

本仕様は検討段階にあり、正規仕様ではない。

---

## 1. 目的

- 人間と LLM が同一フォーマットでドキュメントを扱う
- 正規構造・同一性を LLM が保証する
- 人間は意味理解と判断に集中する
- UI上での回収失敗（セッション切れ等）による再生成を減らす

---

## 2. 基本構造

共通ドキュメントは、以下の構造を持つ。

1. LLM 管理下ブロック（先頭）
2. 人間向け階層リンク行（先頭）
3. ドキュメントタイトル
4. 本文（Human 編集領域）
5. 区切り線
6. 人間向け階層リンク行（末尾）

---

## 3. LLM 管理下ブロック

- HTML コメントとして記述する
- 人間は原則編集しない
- LLM が生成・更新する
- Canonical 情報として扱う

代表的な項目：

- doc_id（唯一の同一性）
- lang（文書言語）
- canonical_title（当該言語でのタイトル）
- source_of_truth（原語）
- translation_of（派生元 doc_id）
- output_mode（canonical-md / ui-copy）
- transport（none / ui-copy）

---

## 4. ドキュメントタイトルの規約

- タイトルは意味・概念の名前であり、人間の理解を最優先とする
- タイトル行は Canonical
- 翻訳により内容が変わってよい（同一性は doc_id が保証する）

---

## 5. ファイル名の規約（原語版）

- ファイル名は配置・参照用の識別子であり、意味・同一性を担わない
- 番号付き形式（NN_）を採用し、順序のためにのみ用いる

---

## 6. 翻訳ドキュメントの規約

- 原語版のみが Source of Truth
- 翻訳版は派生物
- doc_id は全言語で共通
- 翻訳後のファイル名は翻訳語ベースとし、番号（NN_）は全言語で一致させる

---

## 7. Human 編集領域の扱い

- 人間が編集してもよい
- ただし整合性回復責務は LLM にある
- 本文は Non-Canonical（ただし運用上は LLM が管理する）

---

## 8. output_mode と Transport Encoding

### 8.1 デフォルト

- output_mode が未指定の場合、ui-copy とみなす
- 理由：UI のファイルダウンロードはセッション切れ等で回収失敗が起きやすく、
  回収失敗は再生成（計算資産消費・差分発生）につながるため

---

### 8.2 canonical-md

- 正規成果物
- エスケープなし Markdown
- UIファイル、API（JSON文字列→保存）、CLI 等を含む

---

### 8.3 ui-copy

- UI コピー前提の Transport Encoding
- エスケープ対象は「コードフェンス（バッククォート3つ）」のみ
- それを <HL-FENCE> に置換する
- 保存後に <HL-FENCE> を「コードフェンス（バッククォート3つ）」に復元すると正規 Markdown になる

---

### 8.4 file-only（例外運用）

次の条件では ui-copy を使用しない（canonical-md を使用する）。

- <HL-FENCE> 自体を説明対象に含むため、ui-copy での自己言及が混乱を招く場合
- 「コードフェンス（バッククォート3つ）」を本文でそのまま提示する必要がある場合

---

## 9. 正規化方針

- 本仕様確定後：
  - docs/ja-JP/テンプレート/ に移動
  - HLDocS 正規仕様として再発行する
