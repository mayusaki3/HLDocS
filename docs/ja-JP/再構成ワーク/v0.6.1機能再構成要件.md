# v0.6.1機能再構成要件

## 1. 目的と位置付け

v0.7.0がv0.6.1-previewで利用可能とされた機能を、内部構造の同一性を要求せず再現できることを確認するための開発中チェックリストである。本書は移行検討資料であり、確定した仕様の正本ではない。

比較基準は`main`のv0.6.1仕様・テンプレート・プロンプト・実行手順とし、`develop`の再構成仕様だけから旧機能を推測しない。

## 2. 判定規則

各機能は旧版の入力・期待動作・失敗条件を抽出し、v0.7.0の担当仕様と実行経路に対応付ける。仕様の存在だけではPASSとしない。代表正常系・異常系のシナリオを実行または再現可能な形で検証する。

判定はPASS、FAIL、UNDEFINED、BLOCKED、NOT_APPLICABLEとする。後四者をPASSへ読み替えない。意図的に廃止・変更する機能は利用者の明示承認と代替動作・移行影響の記録を必要とする。

検証には対象ブランチ・コミットSHA、比較元のタグまたはコミットSHA、使用仕様、シナリオ、期待結果、実結果、根拠を記録する。リリース時は全必須項目のPASSをmainマージゲートへ含める。

## 4. v0.6.1で未完成と記載された事項

プロンプト・テンプレートのみでの完全自己完結生成、HTML可視化パイプライン、安定した仕様再構成ワークフロー、Traceability移行ワークフロー、バリデータ統合は、v0.6.1機能互換の必須条件には含めない。v0.7.0の独立した新規要件として採否を判断する。

## 5. 未確認事項と次の作業

1. `main`の旧仕様から各機能の規範・正常系・異常系を抽出する。
2. `develop`のCore、State Machine、State、Work、Interaction、Workflow、Capability、Restriction、Toolと対応表を作る。
3. 未再構成のSubFlow、document_type、Traceability、meta/apply、recreate invariant、UI・ui_copy、GitHub非依存運用等の不足を識別する。
4. 不足を埋める仕様を作成し、領域別セルフ検証仕様で検証する。
5. リリース候補のコミットで機能互換シナリオを再実行する。

旧版の詳細確認が完了するまでは、どの項目もPASSと判定しない。

## 6. テンプレート再現方式（検討方針）

- Template Definition(テンプレート定義)は、文書種別仕様・共通規則に基づく構造と制約であり、仕様を正本とする。
- Generated Template(生成テンプレート)は、利用者が確認または利用のため要求した場合にLLMが生成する派生成果物とする。
- 常設のテンプレートファイルはv0.7.0成立の必須条件にしない。ただし生成したテンプレートを利用者が保存することは妨げない。
- 同じ正本仕様から、必須構造・制約に矛盾しないテンプレートを再生成できなければならない。旧ファイルとの文字列一致は要求しない。
- 文書生成とテンプレート確認用生成は異なる要求として扱い、テンプレートを仕様の正本として採用しない。
- 生成プロンプトもテンプレートと同様、仕様を正本とする派生物であり、常設ファイルを必須としない。Workflowは必要な処理時に、適用する仕様から生成指示を構成して使用する。\n- 利用者が確認を求めた場合、Workflowで使用する生成指示に相当する内容を提示できること。内部処理の逐語的な再現や非公開の推論過程の開示は要件としない。\n- テンプレートと生成指示の再現性・適用順序・責務境界はdocument_typeとWorkflowの再構成時に検証する。
