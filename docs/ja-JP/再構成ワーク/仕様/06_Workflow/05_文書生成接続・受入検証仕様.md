# 文書生成接続仕様

## 1. 目的

文書生成SubFlowを既存State/Workflow Planに接続するための成立条件を定義する。受入シナリオと判定方法は「文書生成セルフ検証仕様」に定義する。

## 2. 既存Stateとの整合

現行の変更Stateは`変更調査 → 変更対処 → 変更検証`をdefault_workflow_planとし、情報参照Stateは`情報参照`をdefault_workflow_planとする。文書生成Workflowは現時点で両Stateのavailable_workflowsに登録されていない。

文書の新規作成・更新・翻訳・保存は変更Workとして扱い、確認用の派生構造・生成指示の提示のみを目的とする要求は情報参照Workとして扱う（MUST）。情報参照Workの処理中に保存・正本変更を暗黙に開始してはならない（MUST NOT）。

Workflowの処理仕様が存在するだけでCurrent Workflow Planに追加してはならない（MUST NOT）。Owner=WORKのPlan追加・変更には利用者の明示指示または承認が必要である。

## 3. 接続方式の判定条件

文書生成Workflowを将来独立のWorkflowとして実行する場合、対象Stateのavailable_workflowsとPlanへの接続、既存Workflowとの責務分担、前後関係、Work ContextのArtifact受け渡し、完了条件を仕様として定義しなければならない（MUST）。

変更Stateでは、変更調査によるTarget Listと変更対処による実行結果、変更検証による最終確認を省略してはならない（MUST NOT）。文書生成Workflowを変更対処の代わりに直接起動する接続方式は、これらの契約を満たすまでは許可しない。

情報参照Stateでは確認用派生成果物の提示が情報参照Workflowの範囲内で可能かを検証し、同等機能の重複Plan追加を避ける。

接続方式は、独立WorkflowをPlanに追加せず、既存の変更対処Workflowと情報参照Workflowから必要な文書生成SubFlowを呼び出す方式を採用する。これにより既存のTarget List・変更検証・情報参照の境界を維持する。独立文書生成Workflow仕様は処理設計の参照資料として残すが、Stateのavailable_workflowsおよびdefault_workflow_planには追加しない。

### 3.1 呼出し責務

- 変更調査Workflow：文書変更の対象・現在状態・必要な対処をTarget Listに確定する。
- 変更対処Workflow：Target Listに基づき文書生成SubFlowを呼び出し、権限確認後に反映し結果を記録する。
- 変更検証Workflow：保存済み成果物を再取得し、Work PurposeとTarget Listに照らして独立に検証する。
- 情報参照Workflow：確認用派生成果物を提示するが、保存・変更しない。

## 4. 検証との関係

文書生成の受入シナリオDGEN-01〜18、実施前提、判定方法、検証記録は「文書生成セルフ検証仕様」に従う。接続仕様の成立とセルフ検証PASSは別の判定である。
