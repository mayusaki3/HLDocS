# 文書生成接続・受入検証仕様

## 1. 目的

文書生成Workflowを既存State/Workflow Planに接続するための成立条件と、document_type別の受入シナリオを定義する。これはHLDocS自身のセルフ検証仕様であり、生成された外部成果物のtestspecではない。

## 2. 既存Stateとの整合

現行の変更Stateは`変更調査 → 変更対処 → 変更検証`をdefault_workflow_planとし、情報参照Stateは`情報参照`をdefault_workflow_planとする。文書生成Workflowは現時点で両Stateのavailable_workflowsに登録されていない。

文書の新規作成・更新・翻訳・保存は変更Workとして扱い、確認用の派生構造・生成指示の提示のみを目的とする要求は情報参照Workとして扱う（MUST）。情報参照Workの処理中に保存・正本変更を暗黙に開始してはならない（MUST NOT）。

Workflowの処理仕様が存在するだけでCurrent Workflow Planに追加してはならない（MUST NOT）。Owner=WORKのPlan追加・変更には利用者の明示指示または承認が必要である。

## 3. 接続方式の判定条件

文書生成Workflowを独立のWorkflowとして実行する場合、対象Stateのavailable_workflowsとPlanへの接続、既存Workflowとの責務分担、前後関係、Work ContextのArtifact受け渡し、完了条件を仕様として定義しなければならない（MUST）。

変更Stateでは、変更調査によるTarget Listと変更対処による実行結果、変更検証による最終確認を省略してはならない（MUST NOT）。文書生成Workflowを変更対処の代わりに直接起動する接続方式は、これらの契約を満たすまでは許可しない。

情報参照Stateでは確認用派生成果物の提示が情報参照Workflowの範囲内で可能かを検証し、同等機能の重複Plan追加を避ける。

接続方式は、独立WorkflowをPlanに追加せず、既存の変更対処Workflowと情報参照Workflowから必要な文書生成SubFlowを呼び出す方式を採用する。これにより既存のTarget List・変更検証・情報参照の境界を維持する。独立文書生成Workflow仕様は処理設計の参照資料として残すが、Stateのavailable_workflowsおよびdefault_workflow_planには追加しない。

### 3.1 呼出し責務

- 変更調査Workflow：文書変更の対象・現在状態・必要な対処をTarget Listに確定する。
- 変更対処Workflow：Target Listに基づき文書生成SubFlowを呼び出し、権限確認後に反映し結果を記録する。
- 変更検証Workflow：保存済み成果物を再取得し、Work PurposeとTarget Listに照らして独立に検証する。
- 情報参照Workflow：確認用派生成果物を提示するが、保存・変更しない。

## 4. 受入シナリオ

以下は検証シナリオの定義であり、実行結果ではない。各項目は未実施とする。

| ID | 対象 | 入力と期待結果 |
| --- | --- | --- |
| DGEN-01 | index | 文書階層とリンクを生成し、仕様本文を混入しない |
| DGEN-02 | spec | 宣言的規範を生成し、手順・テストケースを混入しない |
| DGEN-03 | testspec | specとの検証対応を明示し、sec_idを確定・反映する |
| DGEN-04 | note | 仮説・未確定事項を規範として確定しない |
| DGEN-05 | minutes | 日時・議題・合意・未決事項を区別する |
| DGEN-06 | usage | 利用手順を生成し、規範仕様と混同しない |
| DGEN-07 | 更新 | 既存doc_idと既存Traceability識別子を維持する |
| DGEN-08 | 翻訳 | 同一論理文書のdoc_idを維持しlangを変更する |
| DGEN-09 | 確認 | 派生テンプレート構造または説明可能な生成指示のみを提示し保存しない |
| DGEN-10 | 正本不足 | 利用可能情報源を確認後、取得不能を明示して停止する |
| DGEN-11 | 正本矛盾 | 独断で統合せず判断要求へ引き渡す |
| DGEN-12 | 検査失敗 | 違反箇所を特定し修正可能な範囲で再生成する |
| DGEN-13 | 無進展 | 同一原因で無条件再試行しない |
| DGEN-14 | 権限不足 | 検査合格でも保存しない |
| DGEN-15 | 保存失敗 | 成功と報告せず反映状態を区別する |
| DGEN-16 | モード廃止 | meta/apply指定なしで生成・更新でき、常設テンプレート/プロンプトを要求しない |
| DGEN-17 | State境界 | 情報参照Workで正本を変更しない |
| DGEN-18 | Plan境界 | 未登録WorkflowをPlanに暗黙追加しない |

## 5. 検証記録

各シナリオは対象正本の版またはSHA、入力、期待結果、実結果、判定（PASS/FAIL/UNDEFINED/BLOCKED）、発見Issue、修正後再実行を記録する（MUST）。

現時点では全シナリオ未実施であり、PASSと記録してはならない（MUST NOT）。接続が未完了で実行できないシナリオは実施時にBLOCKEDとして記録し、未実施と混同しない。
