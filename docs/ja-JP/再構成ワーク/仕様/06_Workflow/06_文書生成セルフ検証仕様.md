# 文書生成セルフ検証仕様

## 1. 目的と適用範囲

本書はHLDocS自身のセルフ検証仕様である。document_type=specとして管理し、HLDocSが生成した外部成果物のtestspecとは区別する。

文書生成の6種類のdocument_type、識別子・Traceability、更新・翻訳、SubFlow呼出し、State・Plan境界、失敗系を検証する。対象正本は文書共通構造仕様、Traceability仕様、document_type仕様、文書生成SubFlow仕様、文書生成接続仕様、および関係するState・Workflow仕様とする。

## 2. 検証前提と方法

- 新規LLMセッションでも現在のリポジトリ正本を取得して開始できること。過去チャットやLLM_WORKSPACEを検証根拠の正本としない。
- 検証対象ブランチ・対象SHA・仕様パスと版、対象入力、許可された操作範囲を記録する。
- 正常系は生成した成果物を再取得して構造と参照先を照合する。失敗系は模擬入力を明示し、模擬結果を実環境での発生事実と混同しない。
- 既知シナリオ以外にも、識別子の衝突、参照先不在、無権限変更、状態境界の逸脱を探索する。
- 不足情報を推測補完しない。実行できない場合はBLOCKED、期待値が確定しない場合はUNDEFINED、実行した結果の不一致はFAILとして区別する。

## 3. 受入シナリオ

以下は検証シナリオの定義であり、実行結果ではない。各項目は未実施とする。

| ID | 対象 | 入力と期待結果 |
| --- | --- | --- |
| DGEN-01 | index | 文書階層とリンクを生成し、仕様本文を混入しない |
| DGEN-02 | spec | 宣言的規範を生成し、手順・テストケースを混入しない |
| DGEN-03 | testspec | specとの検証対応を明示し、sec_idを確定・反映する |
| DGEN-04 | note | 仮説・未確定事項を規範として確定しない |
| DGEN-05 | minutes | 日時・議題・合意・未決事項を区別する |
| DGEN-06 | usage | 利用手順を生成し、規範仕様と混同しない |
| DGEN-07 | 更新 | 既存doc_idと既存Traceability識別子を維持する |
| DGEN-08 | 翻訳 | 同一論理文書のdoc_idを維持しlangを変更する |
| DGEN-09 | 確認 | 派生テンプレート構造または説明可能な生成指示のみを提示し保存しない |
| DGEN-10 | 正本不足 | 利用可能情報源を確認後、取得不能を明示して停止する |
| DGEN-11 | 正本矛盾 | 独断で統合せず判断要求へ引き渡す |
| DGEN-12 | 検査失敗 | 違反箇所を特定し修正可能な範囲で再生成する |
| DGEN-13 | 無進展 | 同一原因で無条件再試行しない |
| DGEN-14 | 権限不足 | 検査合格でも保存しない |
| DGEN-15 | 保存失敗 | 成功と報告せず反映状態を区別する |
| DGEN-16 | モード廃止 | meta/apply指定なしで生成・更新でき、常設テンプレート/プロンプトを要求しない |
| DGEN-17 | State境界 | 情報参照Workで正本を変更しない |
| DGEN-18 | Plan境界 | 未登録WorkflowをPlanに暗黙追加しない |

## 4. 検証記録

各シナリオは対象正本の版またはSHA、入力、期待結果、実結果、判定（PASS/FAIL/UNDEFINED/BLOCKED）、発見Issue、修正後再実行を記録する（MUST）。

既存の静的照合記録を各シナリオの実行済みPASSとして流用してはならない（MUST NOT）。接続が未完了で実行できないシナリオは実施時にBLOCKEDとして記録し、未実施と混同しない。


## 5. 再検証条件

対象仕様・生成処理・参照規約・State/Workflow接続に影響する変更があれば、差分影響を記録して該当シナリオを再実行する。過去SHAのPASSを現在SHAのPASSとみなさない。
