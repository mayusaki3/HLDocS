# HLDocSシステム起動条件

## 1. 目的

本書は、HLDocSのCoreを起動し、State Machineへの制御移譲を試行できる状態にするための条件を定義する。

## 2. 起動前

HLDocS開始時は、HLDocSシステム起動前として扱う。  
起動前は、本仕様および起動に必要なCore仕様だけを根拠として起動判定を行わなければならない（MUST）。

起動前に、通常運転用のWorkflow、SubFlow、Tool、Stateまたは個別Restriction Setをすべて読み込むことを要求してはならない（MUST NOT）。

## 3. 起動条件

HLDocSシステムを起動するためには、次の条件をすべて満たさなければならない（MUST）。

- HLDocS仕様/規約（正本）の参照先を特定できること。
- 「HLDocSとは」を参照できること。
- 「HLDocSシステム起動条件」を参照できること。
- 「Core仕様」を参照できること。
- Coreが起動時に要求する安全側の基本制御を適用できること。

起動条件は、通常運転で利用するすべての仕様要素が利用可能であることを要求しない。  
通常運転用仕様は、必要になった時点で登録情報および参照規則に従って取得・検証する。

## 4. 正本の情報源

HLDocS仕様/規約（正本）の情報源は、利用者が指定した情報源を使用しなければならない（MUST）。

Version Up(バージョン更新)、移行、再構成、比較その他の理由により、同一仕様の複数の正本候補が存在してよい（MAY）。複数候補が存在することだけを理由として起動不能としてはならない（MUST NOT）。

利用者が複数の情報源を明示した場合は、利用者が指定した優先順位に従う。

利用者指定、対象版、ブランチ、配置先その他の明示的な根拠から現在採用する正本を一意に確定できる場合、その候補を起動判定に使用する。

現在採用する正本を一意に確定できない場合はCanonical Conflict(正本競合)として扱い、同一仕様の複数候補を推測で統合してはならず（MUST NOT）、起動判定に必要な場合は利用者へ確認しなければならない（MUST）。

`canonical_document: true`の候補が複数存在することだけを理由として、それらを自動統合または一律非正本化してはならない（MUST NOT）。

## 5. 起動成立

第3章の条件を満たした場合、Coreを起動してよい（MAY）。  
Core起動が完了した時点を「HLDocSシステム起動完了」とする。

HLDocSシステム起動完了は、通常運転開始を意味しない。

## 6. State Machineへの移譲

Core起動後、CoreはState Machineへの制御移譲を試行しなければならない（MUST）。

- 移譲に成功した場合、通常運転を開始する。
- 移譲に失敗した場合、通常運転を開始してはならず（MUST NOT）、Coreの復旧機構へ移行しなければならない（MUST）。

復旧中は、通常運転用のWorkflowまたはSubFlowを無制限に利用してはならない（MUST NOT）。

## 7. 起動不成立

第3章の条件を満たさない場合、HLDocSシステムを起動してはならない（MUST NOT）。  
不足または不整合を特定できる場合は、利用者へその内容を提示してよい（MAY）。
