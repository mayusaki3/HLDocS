# 状態マシン仕様

## 1. 目的

本書は、HLDocSにおける状態およびWorkflowの管理方法を定義する。

本仕様は、共通仕様成立状態でのみ利用できる。  
共通仕様成立状態でない場合、本仕様を根拠として判断・生成・更新・検証を行ってはならない（MUST NOT）。  
共通仕様成立状態は、「共通仕様成立条件」に従って確認する。

## 2. 状態マシン

HLDocSは、状態マシンによって動作する。  
状態マシンは、現在状態を管理し、状態遷移を制御する。  
Workflowは、現在状態に対応する処理手順を定義する。  
状態およびWorkflowは、本章で定義する一覧によって構成される。

## 3. 状態・Workflow一覧

### 3.1 状態・Workflow一覧

| 状態 | Workflow | 開始条件 |
| ---- | ---- | ---- |
| 開始状態 | 開始Workflow | 作業対象が新しく指示されたとき |
| 待機状態 | 待機Workflow | Workflowが終了し、状態遷移要求が存在しない場合 |

本一覧は、HLDocS状態マシンの構成概念を示すものであり、並び順・管理番号・ファイル構成・分割単位を規定するものではない。  
状態マシンにおける識別単位は、文書番号・ファイル名・分割単位ではなく、本一覧に列挙された状態およびWorkflowそのものである（MUST）。  
したがって状態マシンでは、各状態およびWorkflowに対応する正本仕様が提示されていることを確認しなければならない（MUST）。

Workflowは、本一覧に登録されたもののみ利用できる（MUST）。  
本一覧に登録されていないWorkflowを利用してはならない（MUST NOT）。  
Workflowは、共通仕様成立条件にて定義する仕様要素一覧へ登録されていなければならない（MUST）。  

文書番号・ファイル分割・番号範囲（例：01-05、06-10等）を理由として、状態またはWorkflowが充足していると判断してはならない（MUST NOT）。

## 4. 状態遷移

状態遷移は、現在状態に対応する状態仕様に従って実施しなければならない（MUST）。  
Workflowは状態遷移を要求できるが、自ら状態遷移を実施してはならない（MUST NOT）。  
状態が変化した場合は、現在状態を報告しなければならない（MUST）。  
現在状態が不明な場合は、待機状態へ遷移し、その状態を報告しなければならない（MUST）。

### 4.1 状態引継ぎ情報

参照境界とは、Workflow実行時に参照可能な会話範囲を区切る位置である。  
状態引継ぎ情報とは、状態遷移後のWorkflow実行に必要な情報である。

状態マシンは、状態遷移時に状態遷移位置を参照境界として保持しなければならない（MUST）。
状態マシンは、状態遷移時に現在状態で確定した状態引継ぎ情報を保持しなければならない（MUST）。
ただし、状態引継ぎ情報は、参照境界以前の会話内容の例外として利用できる（MUST）。

Workflowは、状態引継ぎ情報を除き、参照境界以前の会話内容をWorkflow実行の根拠としてはならない（MUST NOT）。  
Workflowは、必要な情報を状態引継ぎ情報、状態遷移後の利用者入力および
参照仕様から取得しなければならない（MUST）。

### 4.2 利用者入力の解釈

状態マシンは、利用者入力を、その役割に従って解釈しなければならない（MUST）。  
利用者入力には、少なくとも次の役割が存在する。

- 目的
- 作業指示
- 作業対象
- 制約
- 参考情報

状態マシンは、利用者入力の役割を他の役割へ変換して解釈してはならない（MUST NOT）。  
目的は、利用者とLLMが共有する作業目標であり、作業指示、Workflow開始条件または実行命令として解釈してはならない（MUST NOT）。  
作業対象、制約および参考情報は、それぞれの役割の範囲内で利用しなければならず、Workflow開始条件または実行命令として解釈してはならない（MUST NOT）。  

Workflowは、作業指示またはWorkflow開始条件を満たした場合のみ開始できる（MUST）。  
状態マシンは、利用者入力、参照仕様またはその他の情報を根拠として、Workflowの選択、Workflow開始条件または作業指示を推測してはならない（MUST NOT）。  
状態マシンは、Workflowの選択、Workflow開始条件または作業指示を一意に決定できない場合、Workflowを開始してはならない（MUST NOT）。  
この場合は、待機状態へ遷移し、利用者へ判断または追加指示を求めなければならない（MUST）。

利用者から「進めて」「続けて」その他これらに準ずる継続指示を受けた場合は、状態マシンは現在状態および待機理由に従って解釈しなければならない（MUST）。  
継続指示は、新たなWorkflowの選択または作業指示として解釈してはならない（MUST NOT）。  
継続指示により処理を再開する場合は、待機理由の解消に必要な範囲のみ実施しなければならない（MUST）。  
利用者の判断、選択または追加指示が必要なケースで、利用者が必要な内容を提示せずに継続指示を行った場合は、状態マシンは必要な判断、選択または追加指示を要求しなければならない（MUST）。

## 4.3 Workflow中断・再開

Workflowは、他のWorkflowまたはSubFlowを実行するため、必要に応じて中断できる（MUST）。  
状態マシンは、Workflow中断時に再開に必要な状態情報を利用可能な状態で保持しなければならない（MUST）。  
状態情報には、WorkflowおよびWorkflowの再開に必要なSubFlowの実行状態を含めなければならない（MUST）。  
状態マシンは、中断中のWorkflowが存在する場合、新たなWorkflowを中断して開始してはならない（MUST NOT）。

中断中のWorkflowが存在する場合、状態マシンは当該Workflowの再開を優先しなければならない（MUST）。  
状態マシンは、中断中のWorkflowが存在する場合、割込みWorkflowの終了後、当該Workflowの再開を要求しなければならない（MUST）。  
Workflow再開時は、中断時の状態情報を用いて処理を継続しなければならない（MUST）。

Workflowは、利用者判断待ちとなった場合、状態マシンへ待機状態への遷移を要求しなければならない（MUST）。

## 4.4 LLM_WORKSPACE

Workflowは、Workflow実行中に必要な一時情報をLLM_WORKSPACEへ保持してよい（MAY）。  
LLM_WORKSPACEの構造、保持対象および管理方法は、 「LLM_WORKSPACE仕様」に従う。

### 4.5 待機状態への遷移

状態マシンは、次のいずれかに該当する場合、処理を停止してはならず（MUST NOT）、待機状態へ遷移しなければならない（MUST）。

- Workflowが終了し、状態遷移要求が存在しない場合
- 利用者の判断、選択または追加指示が必要な場合
- 利用者への確認を行わずに作業を継続すると、仕様上禁止される推測または補完が必要となる場合
- 複数の実行方法が存在し、仕様のみから一意に決定できない場合
- 利用者への確認を行うことなく処理を継続すると、成果物、作業範囲または処理方針が変化する場合

待機状態へ遷移する場合、状態マシンは、少なくとも次の内容を利用者へ報告しなければならない（MUST）。

- 現在状態
- 待機へ遷移した理由
- 利用者に求める判断または入力
