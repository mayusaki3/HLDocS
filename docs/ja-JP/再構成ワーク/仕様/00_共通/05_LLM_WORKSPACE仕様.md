# LLM_WORKSPACE仕様

## 1. 目的

本書は、HLDocSにおけるLLM_WORKSPACEの管理方法を定義する。  
LLM_WORKSPACEは成果物ではなく、HLDocS管理下で行う作業の一時記憶領域としてLLMが使用する管理領域である。  

本仕様は、共通仕様成立状態でのみ利用できる。  
共通仕様成立状態でない場合、本仕様を根拠として判断・生成・更新・検証を行ってはならない（MUST NOT）。  
共通仕様成立状態は、「共通仕様成立条件」に従って確認する。

---

## 2. 適用範囲

本仕様は、HLDocS仕様/規約およびHLDocS管理下で行う作業全般に適用する。

---

## 3. 基本方針

LLM_WORKSPACEは、HLDocS管理下で行う作業の状態を記憶しておくための一時記憶領域であり、
リポジトリ直下に、次のフォルダ構成で作成しなければならない（MUST）。

```shell
LLM_WORKSPACE
├─Handover
├─Request
└─Worklog
```
各フォルダには、次項以降で説明する情報を格納できる (MAY)。  
情報を格納すべきかどうかは、新しく作業を開始したときに、LLM_WORKSPACE内の情報で作業が再開できるかを判断基準としなければならない（MUST）。  

### 3.1 Handover

Handoverは、作業中に発生した、他のプロジェクトへの申し送り情報を一時的に保管する場所である。  
LLMは、作業の中で申し送りすべき情報が発生した場合、ここにファイルを作成し、利用者に申し送りをするよう依頼することができる (MAY)。  
利用者は、申し送り先にファイルを渡し、Handoverから削除する責務を負う。  
申し送り先からの応答については、利用者がチャットなどで応答を代行する。

### 3.2 Request

Requestは、作業中に発生した利用者からの要求や、他のプロジェクトからの申し送り情報で受けた内容を、TODOとして一時的に保管する場所である。  
LLMは、チャットを通じて、要求や申し送りを受け取ることができ、受け取った場合は自身でRequestに保存しなければならない（MUST）。  
LLMは、利用者の指示がない限り、Request内のファイルを読み処理してはならない（NOT MUST）。
Request内のファイルに書かれた内容を、採用するかどうかを判断するのは利用者の責務であり、LLMが判断してはならない（NOT MUST）。
利用者が採用/不採用と判断した場合、その情報をを作業記録とWorklogに反映後、Requestからは削除しなければならない（MUST）。

### 3.3 Worklog

Worklogは、現在の作業の状態を一時的に保管する場所である。  
一番の目的は、新しく作業を始めた場合でも、この情報があれば作業が再開できることである。
そのため、以下の情報を保管しなければならない（MUST）。

- 作業ロードマップがある場合、ロードマップ全体と、次は何をするのかの情報
- 成果物を作成・更新するために必要な情報の記録
  - Requestで採用された内容の一時記録
  - 検討・検証結果の一時記録

これらの情報は、 savepoint.md に記録し、保存した追加のファイルの存在は savepoint.md に記録しなければならない (MUST)。
情報の保管タイミングは、SavePointルールに従わなくてはならない（MUST）。  

保存した情報は、以下のように不要になったタイミングで消去しなくてはならない（MUST）。

- 作業ロードマップ全体が終了した場合、作業ロードマップ情報
- 記録された内容が、成果物に反映された後の一時記憶

### 3.4 SavePointルール

SavePointは、作業を再開する時に、Workflow再開可能な状態をLLMが復元するための仕組みである。  
SavePointに保存する前に情報が失われた場合、LLMはSavePointに保存した情報で作業を再開できる。例えばWorkflowの再実施で収集できるような情報などは保存しなくてよい（MAY）。
SavePoint保存タイミングにより、SavePointの情報より新しい正本情報等が保存されている可能性があるため、作業再開時には、SavePointに保存された作業ロードマップに従い、作業予定だった対象の状態を確認しなければならない (MUST)。
SavePointへの保存は、Workflow開始時、Workflow終了時、または利用者がSaveを指示した場合に実施しなければならない (MUST)。

---

## 4. 利用

WorkflowおよびSubFlowは、必要に応じてLLM_WORKSPACEを参照してよい（MAY）。  
WorkflowおよびSubFlowは、LLM_WORKSPACEのみを根拠として成果物を生成してはならない（MUST NOT）。  
成果物の生成・更新・検証は、正本仕様および利用者入力を根拠としなければならない（MUST）。

---

## 5. 状態マシンとの関係

状態マシンは、Workflow中断時に再開に必要な情報をLLM_WORKSPACEへ保持しなければならない（MUST）。

---

## 6. Workflow・SubFlowとの関係

WorkflowおよびSubFlowは、LLM_WORKSPACEを実行時管理領域として利用してよい（MAY）。

LLM_WORKSPACEはWorkflow間の成果物共有を目的として利用してはならない（MUST NOT）。

成果物をWorkflow間で利用する場合は、正本仕様または利用者から提示された成果物を利用しなければならない（MUST）。
